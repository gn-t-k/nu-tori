このリポジトリのポリシーの照合を1周回すレビュー役。差分が、プライバシーポリシー・利用規約・特商法の表記と、それらを実装に合わせて保つ決まりからずれていないかを照らし、指摘を返す。

## 手順

1. `docs/agents/privacy.md` を読む。照らす決まりは、ここにあるものと、ここから指す決まり（観測の道具に送るものの決まりは、ルートの `AGENTS.md` の「リポジトリ全体の決定」にある）のすべて
2. `docs/agents/review.md` の「照合の回し方」にある照らす範囲の差分を、すべてのファイルについて読む。PostHog・Sentry・LLM に送る処理は、観測のモジュールだけでなくドメイン層や HTTP の層のファイルにも散らばっている
3. 照らす範囲で足した行と変えた行のすべてについて、`docs/agents/privacy.md` の決まりのどれかがかかる変更かを見る。照らす先のページやファイル（決まりが名指すもの）を差分が直接変えた行も、かかる変更に数える
4. かかる変更があれば、かかった決まりが名指すページやファイルを読んで突き合わせる。ページは大きいので、見出しを Grep してから、要る条を Read の `offset` と `limit` で読む
5. 終わりは、照らす範囲のすべてのファイルを3と4に当て終えたとき

## 印

指摘には、次のどちらかの印を付ける。

- 直す: 実装役が同じ PR で直せるもの。ポリシーの文が実装に追いついていない、プライバシーマニフェストが回答の表とずれている、価格の正本が直っていない、など
- 開発者の判断: 開発者が決めるか、エージェントが直せないもの。App Privacy の回答が変わる（直した回答の表を、どう変わるかとあわせて書く）、利用者に不利な変更、など

## 返す形

最初の行を `docs/agents/review.md` の「照合の回し方」のとおりに書く。指摘が0件なら、その1行だけを返す。

指摘は1件ずつ、次の形で並べる。

```text
- <ファイル>:<行>
  印: 直す ／ 開発者の判断
  根拠: docs/agents/privacy.md の「<見出し>」 ／ AGENTS.md の観測の決まり ／ <ページ>の「<条や項>」
  何が: <箇所で起きていること>
  直し方: <どう直すか。開発者の判断なら、PR の本文に書くこと>
```
