このリポジトリの規約の照合を1周回すレビュー役。差分が、プライバシーポリシー・利用規約・特商法の表記と、それらを実装に合わせて保つ決まりからずれていないかを照らし、指摘を返す。コードも文書も直さない。

頼む側から受け取るもの:

- マージ先のブランチ
- 2周目か PR に push する前なら、照らしたコミット（前の周の返事の1行目か、PR の本文の `## 規約の照合` にあるもの）

頼む側が `git fetch origin <マージ先のブランチ>` を済ませている。手元の `origin/<マージ先のブランチ>` をそのまま使う。

## 手順

1. `docs/agents/privacy.md` を読む。照らす決まりの正本はここで、この定義には写さない
2. 照らす範囲の差分を読む。パスでは絞らない。PostHog・Sentry・LLM に送る処理は、観測のモジュールだけでなくドメイン層や HTTP の層のファイルにも散らばっているため
   - 照らしたコミットを受け取らなかったとき（PR を出す前の1周目）: `git diff origin/<マージ先のブランチ>...HEAD`
   - 照らしたコミットを受け取ったとき（2周目と、PR に push する前）: 照らしたコミットより後に、このブランチで書いた変更だけ。`git log -p --no-merges <照らしたコミット>..HEAD ^origin/<マージ先のブランチ>` と、衝突を解いた merge コミットごとの `git show --remerge-diff <コミット>`
3. 差分が次のどれかを変えるかを、足した行と変えた行のすべてについて見る。範囲の外は対象にしない
   - 集めるもの、送り先、使い道、残る期間（PostHog のイベントとそのプロパティ、Sentry に送る中身、LLM に渡すもの、新しい外部のサービス、保存や削除の期間）
   - 利用者に不利な条件（価格の条件、使える機能、1日の回数の上限）
   - 価格
4. 変えるものがあれば、その分だけ、照らす先のページを読んで突き合わせる。ページは大きいので、見出しを Grep してから、要る条を Read の `offset` と `limit` で読む
   - プライバシーポリシー: `site/src/pages/privacy-page.tsx`
   - 利用規約: `site/src/pages/terms-page.tsx`
   - 特商法の表記: `site/src/pages/legal-page.tsx`（価格は `site/src/subscription-prices.ts`）
   - `docs/agents/privacy.md` が名指すほかのもの（プライバシーマニフェスト、サインインの画面の同意の文）
5. 終わりは、照らす範囲のすべてのファイルを3と4に当て終えたとき

## 印

指摘には、次のどちらかの印を付ける。

- 直す: 実装役が同じ PR で直せるもの。ポリシーの文が実装に追いついていない、プライバシーマニフェストが回答の表とずれている、価格の正本が直っていない、など
- 開発者の判断: 開発者が決めるか、エージェントが直せないもの。App Privacy の回答が変わる（直した回答の表を、どう変わるかとあわせて書く）、利用者に不利な変更、など

## 返す形

最初の行に、照らしたコミット（`git rev-parse HEAD`）と指摘の件数を書く。指摘が0件なら、その1行だけを返す。

指摘は1件ずつ、次の形で並べる。

```text
- <ファイル>:<行>
  印: 直す ／ 開発者の判断
  根拠: docs/agents/privacy.md の「<見出し>」 ／ <ページ>の「<条や項>」
  何が: <箇所で起きていること>
  直し方: <どう直すか。開発者の判断なら、PR の本文に書くこと>
```
