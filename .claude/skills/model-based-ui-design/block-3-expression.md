# 終盤ブロック：表現設計と大詰め（⑥ ⑦）

[SKILL.md](SKILL.md) の終盤ブロック。⑥⑦は一体（⑥＝プラットフォーム適合・レイアウト＋詳細遷移、⑦＝表現＝インタラクション/モード＋ルック&フィール）。ビジュアル（色/タイポ）は最後の10%。⑦の往復は [design-sync.md](design-sync.md)。出口は末尾の**終盤ゲート**。

**用語（このブロック固有）**:
- **フォームファクタ** — 製品が動く機器の形態区分。主にデスクトップ / モバイル / タブレット等の画面・入力様式の括り。これと「プラットフォーム（iOS/Android 等の OS）」は別レイヤーで、⑥では先にフォームファクタを決め、次に OS のパターンへ適合させる。
- **パターン** — 再利用される定型的な解決（タブバー、リスト-詳細 等）。
- **イディオム** — そのプラットフォーム特有の慣用表現（iOS の戻る矢印、システム標準フォント等）。OS が「使い慣れた表現」として提供するもの。

---

## ⑥ プラットフォーム適合・レイアウト設計 → レイアウト設計図

フォームファクタ非依存の汎用モデルを、特定プラットフォームの条件に適合させる。産出物は `06-layout.md`。

1. **フォームファクタ決定**: コンセプト/UC に照らし最も実現可能性が高いものを選ぶ。デザインだけで決めず、**必ず技術者の判断を入れる**（開発体制・技術的負債）
2. **プラットフォーム適合**: OS 公式ガイドラインの**パターンとイディオム**に準拠（iOS なら標準タブバー/ナビバー、システム標準フォント）
3. **③フレーム構造を詳細化**: UI の分割方法・ペインの役割を具体化
   - デスクトップ: マルチウインドウ、3ペイン（サイドバー＋コンテンツ＋インスペクタ 等）
   - モバイル（画面が狭い）: **レイアウト3段活用** ＝ 3つのナビ様式を**組み合わせて**階層を表現する（1画面の3領域ではない）。**リスト**（概要一覧）／**ドリルダウン**（一覧から詳細へ潜る）／**タブ または スタック**（トップ階層の切替・積み重ね）。一時的な表示は**シート**で
4. **ナビの詳細遷移を決定**: ⑤の全体像 → 具体的な状態遷移・アニメ・モーダルの出方

忠実度: 中忠実度ワイヤー（ペイン分割・情報階層は正確、着色は最小）。**ここはまだ DesignSync 往復ではない**。描き方は [visual-output.md](visual-output.md)。

**よくある罠**: iOS/Android の無理な共通化（OS 固有の特徴が削げ、両者に使いにくい）／カスタムフォント乱用（容量肥大・ライセンス。システム標準を使う）／フルスクリーンの無闇な採用（マルチタスク阻害＝モーダル化）／独自タブバーの再発明（現在地喪失・アクセシビリティ低下）。

## ⑦ 表現設計（インタラクション＋ルック&フィール）→ UI コンポーネント

構造を固めた**後**の最後の10%。インタラクション 30% ＋ ルック&フィール 10%。

### 手順A：インタラクション設計

1. 操作方法を決める（テキスト入力/編集・ポインター・タッチジェスチャ・スクロール・Undo/Redo・フィードバック）
2. **モードをどこにどう組み込むか**を決める。原則**モードレス**（ユーザーの行動を状態で縛らない）:
   - **名詞→動詞方式**: 対象（名詞＝オブジェクト）を選んでからコマンド（動詞＝アクション）を実行する操作順序にする
   - ファーストビューは操作対象オブジェクト（名詞）起点（「〜管理」「追加する」＝動詞を並べない）
   - モードレスを保つ置換:
     - **アプリケーションモーダル**（アプリ全体をブロックするモーダル）→ **ドキュメントモーダル**（対象の領域内に限定。macOS のシート等）
     - ダイアログ → **インライン通知**（画面を覆わず、その場で知らせる）
     - 一時的な操作 → **擬似モード（バネ式 / spring-loaded）**（キーを押している間だけ有効で、離すと元に戻る一時モード）

### 手順B：ルック&フィール設計

3. ④コンセプト（提供したい体験・設計思想・ブランドのデザイン言語）＋プラットフォームのパターン/イディオムを基準に、色・タイポ・グラフィックを試行錯誤（固めた構造の上だから余裕を持って探れる）

### コンポーネント化と往復

単位ビューを**コンポーネント単位**にして HTML 化し、Claude Design の design-system と往復する。産出物は `07-components/`。手順・前提・@dsCard・フォールバック、および「本書の対象外を拡張する」位置づけは [design-sync.md](design-sync.md)。

**よくある罠**: 多重モーダルが深すぎ（モードの中からモードを開くのが**2〜3階層を超える**と、元タスクを忘れて現在地を見失う＝終盤ゲートの閾値の根拠）／モーダルダイアログにバツボタン（唯一の否定アクション「キャンセル」と区別不能になる）／その他⑥と共通の罠（iOS/Android 共通化・カスタムフォント・フルスクリーン）は⑥を参照。
