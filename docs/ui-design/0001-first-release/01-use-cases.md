# ユースケースモデル

入力: `00-persona-model.md`、`00-behavioral-scenarios.md`
分類は対象物軸。

用語メモ: **目標** は期限と目標体重の組み。**1日の目安** は、目標に向けて1日に食べる量の目安（カロリーと PFC）。名前は③で見直す。

優先度は「初回リリースで必須」を **必須**、「無くてもユーザーの2操作は成り立つ」を **推奨** とする。

## 検討して入れなかったもの

| 候補 | 入れない理由 |
|---|---|
| 運動の記録・ワークアウトの取り込み | 消費量は体重の傾向と食べた量から推定する（目安_2）。ユーザーの2操作を増やさない |
| 食品の検索・バーコード読み取り | 撮る・文章で書くで足りる。精度は量の修正で上げる（食事_6、_11） |
| FoodNoms・MacroFactor との直接の連携 | ヘルスケアを介したやりとり（体重_3、目安_6、食事_10）で足りる |
| 体重の当てずっぽう入力 | 体重は厳密に測れる値なので、測った値だけを受け付ける |
| 課金 | 将来の設計記録で扱う |
| AI に頼んで記録を直す（例:「さっきの唐揚げは竜田揚げだった」と会話で伝える） | 将来の機能。画面での修正（食事_6、_11〜_14）と同じ操作を AI が代わりに行う形にする。会話の構造（会話 → 発言）はそのまま使える |
| 自動で出すアドバイス（食後のひとこと、前日のまとめ。旧 フィードバック_5） | アドバイスを求めない人がいる。求められていない回答にトークンを使わない。尋ねられたときだけ答える（フィードバック_1、_2） |
| 食事区分の振り分け（旧 食事_3） | 1日3食とは限らないので、朝食・昼食・夕食の区分を設けない。食事は時刻で並べる |
