# 行動シナリオ

> ペルソナモデルの Tさん・Mさんが nu-tori でとる行動。ユーザーに求める操作は「毎朝の体重の入力」と「食事の写真を撮る」の2つだけで、それ以外はシステムが引き受ける前提で書いている。
> 【仮置き】はプロダクトオーナーの確認が済んでいない前提。

## 決まった前提

- 撮った食事は、推定結果を確認せずに食べ始めてよい。確認や修正はあとから任意でする
- 「何も入力しないよりは、当てずっぽうでもよいから何か入力する」。撮り忘れた食事は文章でも受け付ける
- 消費量は MacroFactor と同じ考え方で扱う。運動データを入れなくても、体重の傾向と食事量からシステムが消費量を推定し、1日の目安を調整する
- 1日の食事へのフィードバックは初回リリースに入れる。習慣化を支える中心の仕組みとする
- 課金は将来入れる。初回リリースの対象外

## S1 はじめて使う（Tさん）

1. Tさんは nu-tori を入れて開く。nu-tori はヘルスケアへのアクセス許可を求め、Tさんは許可する
2. nu-tori はヘルスケアから身長・体重・生年月日・性別・歩数を読み込み、読み取れた値を並べる。身長と生年月日が入っていなかったので、Tさんはその2つだけ入れる
3. nu-tori は今の体重を尋ね、Tさんは入力する
4. Tさんは「減量」を選ぶ
5. nu-tori は、期限と目標体重の組み合わせを「ゆるめ」「標準」「ハード」の3つ提案する。日常の活動量はヘルスケアの歩数から見積もる。【仮置き】歩数が取れないときは、「ほぼ座り仕事／立ち仕事が多い／よく動く」から1つ選んでもらう
6. Tさんは2か月後に間に合う「ハード」を選ぶ。nu-tori は、ハードだとどのくらい大変かをひとことで伝える
7. nu-tori は1日の目安（カロリーとタンパク質・脂質・炭水化物）を決めて、「あとは朝に体重を測って、食べるときに撮るだけ」と伝える
8. nu-tori は朝の体重と食事どきに通知してよいか尋ね、Tさんは許可する

## S2 はじめて使う（Mさん）

1. Mさんはヘルスケアの許可を出す。身体データと体重はすべてヘルスケアから入る
2. Mさんは MacroFactor で決めた目標があるので、提案を選ばずに期限と目標体重を自分で入れる

## S3 毎朝、体重を測る（Tさん／Mさん）

1. Tさんは出勤前に体重計に乗る。nu-tori の通知をタップすると、前日の値が入った体重の入力欄が開く。Tさんは数字を直して記録する
2. 記録したあとで打ち間違いに気づき、Tさんはその日の体重を直す
3. 【仮置き】Mさんの体重はヘルスケア経由で入り、Mさんは何もしない（体重計がヘルスケアと連携している場合）
4. 記録すると、nu-tori は体重の傾向（日々のブレをならした線）を見せる
5. 【仮置き】測り忘れた日は、昼までに1回だけ知らせる。それでも入らなければ空欄のままにする。消費量は傾向から推定するので、数日抜けても目安の調整は続けられる

## S4 食べるときに撮る（Tさん）

1. 出勤前、Tさんは朝食を前に nu-tori を開く。カメラがすでに起動しているので、そのまま撮る
2. nu-tori は写真から料理と量を推定し、カロリーと栄養を記録する。撮影時刻から「朝食」に振り分ける。Tさんは確認せずに食べ始める
3. 職場の昼食も同じように撮る
4. 夜、皿洗いをしながら子どもの残したご飯をつまんでしまう。写真は撮れなかったので、あとで「子どもの残りのご飯とからあげを少し」と打ち込む。nu-tori は文章からおおよその量を推定して記録する
5. 子どものおやつを間違えて撮ってしまったので、Tさんはその記録を消す
6. Tさんの食事の時刻は日によってずれる。nu-tori は撮影時刻から Tさんのいつもの食事どきを学び、通知の時刻を合わせる

## S5 あとから精度を上げる（Mさん）

1. Mさんは作り置きの鶏むね肉とご飯を撮る
2. 夜、その日の記録を見ると、ご飯が「普通盛り（推定）」になっている。Mさんはご飯を「180g」に直し、nu-tori はその日の合計を計算し直す
3. Mさんは食事ごとの栄養の内訳を開き、ビタミンやミネラルも確かめる
4. 翌日同じ作り置きを撮ると、nu-tori は前日の修正を覚えていて、はじめから 180g で推定する

## S6 今日の食事のフィードバックを受け取る（Tさん）

1. 夜遅くに最後の食事を撮ると、nu-tori は今日の食事がどうだったかをひとことで伝える（例: 「今日はタンパク質がしっかりとれた日でした」）
2. 続けて、次の食事でできることをひとつ伝える（例: 「明日の朝はプロテインを朝食と一緒に」）。Tさんは数字の意味を知らなくても、次に何をすればいいかわかる
3. Tさんはこの毎晩のひとことを楽しみにして、撮るのを続ける

## S7 目安が調整される（Tさん／Mさん）

1. 使い始めて1週間たつと、nu-tori は体重の傾向と食べた量から Tさんの実際の消費量を推定し、1日の目安を調整する
2. Tさんは「目安が少し変わりました」という知らせを見る。細かい理由は読まない
3. Mさんは同じ知らせから、推定した消費量と目安がどう変わったか、なぜ変わったかを確かめる

## S8 振り返る（Tさん）

1. 週末、nu-tori は1週間の体重の傾向と食事の傾向をまとめて見せる。期限までに間に合うペースかも伝える
2. 体重が思うように減っていなくても、nu-tori は傾向と次にできることを伝える。Tさんは落ち込まずに続ける
3. Tさんは気になった日を開き、その日に撮った食事の写真を並べて見返す

## S9 目標を切り替える（Mさん）

1. 大会が終わり、Mさんは増量期に入る。「増量」を選び直し、期限と目標体重を入れる
2. nu-tori は新しい目標にあわせて1日の目安を決め直す

## システム外の事柄（設計対象外）

- 体重計に乗ること、食事を用意すること、食べること、皿洗い
- ヘルスケアアプリ自体の操作、体重計とヘルスケアの連携設定
- チョコザップでのトレーニング、プロテインの購入
- 課金（将来の設計記録で扱う）
- 【仮置き】アカウント登録。初回リリースでは設けず、データは端末と iCloud に置く
- 【仮置き】FoodNoms・MacroFactor とのデータ連携。初回リリースでは扱わない
