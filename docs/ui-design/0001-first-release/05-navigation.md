# ナビゲーション構造

入力: `03-concept-model.md`、`04-concept.md`、`01-use-cases.md`

## 根（目標地点）

- **タイムライン**（日付で区切った集計ビューを、古い日から今日へ1本に並べたもの。新しいものが下に来て、開くと今日の一番新しい位置にいる）。最重要タスク「食事を撮る」は、タイムラインの下の入力欄から直接できる
- 根はこの1つに絞り、タブは持たない。使う頻度が圧倒的に高いのは記録の作業なので、見渡す場所はタブにしない。タイムラインのナビゲーションバーのすぐ下に1日の丸（その日の食べた量と、体重を記録したか）を日ごとに並べ、丸から日のまとめを開く。目標は日のまとめから開く
- 目標を立てる前は、「目標を立てる」を知らせとしてタイムラインに出す。起動直後に目標の設定を求めず、ユーザーが自分のタイミングで立てる（S1、目標_7）

骨組みは次の案をプロトタイプで比べて決めた（`prototype/0001-navigation`、`prototype/0001-timeline`、`prototype/0001-tabs`、`prototype/0001-chat-rings` の各ブランチ）。

| 案 | 結果 |
|---|---|
| 2タブ（今日／目標） | 採らない。目標を開く頻度に対して、タブは場所を取りすぎる |
| タイムラインだけ | 採らない。目標期間の傾向、目安の推移、目標の切り替えの入口が弱い |
| タブなし＋一番上に目標の要約・ファインダー・習慣トラッカー・1日の目安 | 採らない。一番上が詰まる。新しいものを上に並べると入力欄から遠く、下に並べると上に集めたものとぶつかる |
| 2タブ（今日／タイムライン） | 採らない。食事と栄養の情報と、体重と目標の情報が、別々の場所に散らばる |
| 2タブ（タイムライン／進み具合） | 採らない。同じ理由 |
| タブなし＋一番上に1日の丸の帯＋丸から日のまとめ（シート） | **採る**。まとめて見せる情報を1日の丸に詰め、詳しくは日のまとめに置く。帯1本で収まるので、タブを足さずに済む |

## 1. トップダウン（根から）

概念モデルのオブジェクトと関連を、根から素直にたどった。

```mermaid
flowchart TD
  Signin[サインイン] --> Today[タイムライン]
  Today --> Shot[撮影]
  Today --> TextMeal[文章で記録]
  Today --> WeightIn[体重の入力]
  Today --> WeightRec[体重記録の詳細]
  Today --> Meal[食事]
  Meal --> Dish[料理と材料]
  Today --> Convs[会話の一覧]
  Convs --> Conv[会話]
  Today --> Goal[目標]
  Goal --> Targets[1日の目安の推移]
  Goal --> Weekly[週の振り返り]
  Goal --> PastGoals[過去の目標]
  Goal --> GoalSetup[目標の設定]
  Today --> Account[アカウント]
```

## 2. ボトムアップ（目標地点から逆にたどる）

詳細ビューを目標地点に置き、そこへ来る動線を逆にたどった。

```mermaid
flowchart BT
  Meal[食事] -->|時系列の食事| Today[タイムライン]
  Meal -.->|記録の直後| Today
  Weight[体重] -->|入力欄・知らせ・体重記録| Today
  Goal[目標] --> DaySum[日のまとめ]
  DaySum -->|1日の丸| Today
  Goal -->|目安の変更| Today
  Goal -->|目安の変更・達成・期限の知らせ| Notice([通知])
  Weekly[週の振り返り] -->|振り返りのカード| Today
  Weekly --> Goal
  Day[過去の日] -->|上へ| Today
  Day --> Weekly
  GoalSetup[目標の設定] -->|目標の知らせ| Today
  GoalSetup --> DaySum
  GoalSetup -->|目標を切り替える| Goal
  Conv[会話] -->|その時刻に並ぶ| Today
  Account[アカウント] --> Today
```

| 目標地点 | そこへ来る動線 | 根拠ユースケース |
|---|---|---|
| 食事 | タイムライン → 食事 ／ 記録の直後 → 食事（任意） | 食事_5,6,8,11〜14 |
| 体重 | タイムラインの入力欄の体重・体重の知らせ・体重記録 → 体重 | 体重_1,2 |
| 過去の日 | タイムラインを上へ ／ 週の振り返り → 日 | 食事_9、フィードバック_3 |
| 日のまとめ | タイムラインの1日の丸 → 日のまとめ | 体重_4、フィードバック_4,6 |
| 目標 | 日のまとめ → 目標 ／ タイムラインの目安の変更 → 目標 ／ 目安の変更・達成・期限の知らせ → 目標 | 体重_4、目安_4,5、目標_5,6,8,9、フィードバック_4 |
| 週の振り返り | タイムラインの振り返りのカード ／ 目標 → 週の振り返り | フィードバック_3 |
| 目標の設定 | タイムラインの目標の知らせ（目標を立てる、次の目標を選ぶ） ／ 日のまとめ → 目標を立てる・次の目標を選ぶ ／ 目標 → 目標を切り替える | 目標_1〜5,7〜9 |
| 会話 | タイムライン（その時刻に並ぶ） | フィードバック_1,2 |
| アカウント | タイムライン | アカウント_2、身体データ_2、許可_1 |

ボトムアップで新たに出た経路:

- タイムラインの目安の変更 → 目標（変更の理由を知りたいとき）
- 目安の変更・達成・期限の知らせと iPhone の通知 → 目標
- 記録の直後 → その食事（任意。見なくてよい）
- タイムラインの振り返りのカード → 週の振り返り

## 3. 重ね合わせと差異の解消

| 差異 | 片方だけにあった側 | 解消 |
|---|---|---|
| タイムラインの目安の変更 → 目標 | ボトムアップ | OR 採用。変更の理由は目標の中の目安の推移にまとめて置く |
| 通知から目標へ直接入る経路 | ボトムアップ | OR 採用。通知から入ったビューは、戻るとタイムラインに着く |
| 記録の直後 → 食事 | ボトムアップ | OR 採用。ただし記録後はタイムラインに留まるのが既定で、食事は任意に開く（確認を強制しない） |
| タイムライン → 週の振り返り | ボトムアップ | OR 採用。週の区切りに振り返りのカードを差し込む |
| 撮影（独立ビュー） | トップダウン | 作り直し。撮影はタイムラインの下の入力欄の「撮る」から行う |
| 会話の一覧 | トップダウン | 作り直し。一覧ビューを作らず、会話はタイムラインにその時刻の出来事として並べる |
| 1日の目安の推移（独立ビュー） | トップダウン | 作り直し。目標の中に並べる |
| 体重記録の詳細（独立ビュー） | トップダウン | 作り直し。体重記録は属性が少ないので、値と直近の傾向はタイムラインの行に出し、目標期間の傾向は目標に置く。体重のビューは入力と修正だけにする |
| 過去の目標 | トップダウン | OR 採用、優先度は低。目標の一番下に並べる。空なら出さない |
| 文章で記録（独立ビュー） | トップダウン | 作り直し。会話と同じ入力欄に書いて送り、食事の記録か会話かをアプリが読み分ける |
| 日のまとめ | ボトムアップ | OR 採用。1日の丸から開き、その日の食べた量、体重、目標の要約をまとめる。目標はここから開く |

## 統合後のナビゲーション構造

```mermaid
flowchart TD
  Signin[サインイン] -->|済んだら| Today
  subgraph Root[タイムライン]
    Today[タイムライン]
    Today -->|撮る・写真を選ぶ| Today
    Today -.->|記録の直後・任意| Meal[食事]
    Today --> Meal
    Today --> Composer[入力欄]
    Composer -->|体重| Weight[体重]
    Today --> Weight
    Today --> Weekly[週の振り返り]
    Weekly -->|日| Today
  end
  Today -->|1日の丸| DaySum[日のまとめ]
  DaySum -->|この日を見る| Today
  DaySum --> Goal[目標]
  DaySum --> Weekly
  Today -->|目安の変更| Goal
  Notice([通知]) --> Goal
  Goal --> Weekly
  Today -->|目標の知らせ| GoalSetup[目標の設定]
  DaySum -->|目標を立てる・次の目標を選ぶ| GoalSetup
  Goal -->|目標を切り替える| GoalSetup
  Today --> Account[アカウント]
```

- 許可（ヘルスケア、通知、カメラ）は、それが要る操作の中で求める。ヘルスケアの読み取りは初めて体重を入れるときか目標を立てるとき、書き込みは初めて食事を記録したあと、通知は初めて体重を記録したあと、カメラは初めて「撮る」を押したとき

## 目標の状態と入口

| 状態 | タイムラインの知らせ | 日のまとめ | 目標ビュー |
|---|---|---|---|
| 目標がない | 使い始めに「目標を立てる」 → 目標の設定 | 「目標を立てる」 → 目標の設定 | 開かない |
| 進行中 | 出さない | あと何 kg・あと何日・間に合うペースか → 目標 | 傾向、目安の推移、週の振り返り、目標を切り替える |
| 期限より前に達成（傾向の線で判定） | 達成したことと「次の目標を選ぶ」 | 達成したことと「次の目標を選ぶ」 → 目標 | 達成したことと次の目標案。選ぶまで今の目標を続ける |
| 期限が来た | 結果と「次の目標を選ぶ」 | 結果と「次の目標を選ぶ」 → 目標 | 結果、体重の歩み、次の目標案 |
| 期限後に選ばなかった | 今の体重を保つ目標に切り替えたことと「次の目標を立てる」 | 今の体重を保つ目標（期限なし）の要約と「次の目標を立てる」 → 目標 | 今の体重を保つ目標。前の目標は過去の目標に移る |

文言と演出は⑦で決める。

## 多重度から導いた表示パターン

| 関連 | 多重度 | 表示パターン | 置き場所 |
|---|---|---|---|
| アカウント → ユーザー | 1 | 単体 | アカウント |
| ユーザー → 現在の目標 | 0..1 | 単体＋空表示 | 日のまとめに要約。空なら日のまとめとタイムラインの知らせに「目標を立てる」。詳細は目標 |
| ユーザー → 過去の目標 | 0..n | 一覧＋空表示 | 目標の一番下。空なら出さない |
| 目標 → 1日の目安 | 1..n | 一覧（最新を強調） | 目標の中。1日の丸は最新の目安と比べる。週の振り返りも、この適用期間ごとに並ぶ |
| ユーザー → 体重記録 | 0..n | 一覧＋空表示 | タイムライン。今日の分が空なら入力欄の体重を目立たせ、いつもの時刻を過ぎたら知らせを出す |
| ユーザー → 食事 | 0..n | 一覧＋空表示 | タイムライン。空なら記録を促す |
| 食事 → 料理 | 0..n | 一覧＋空表示 | 食事の中。空なら「推定中」または「推定できなかった」 |
| 料理 → 材料 | 1..n | 一覧 | 食事の中、料理の下。量はその場で直す |
| ユーザー → 会話 | 0..n | 一覧＋空表示 | タイムライン。入力欄のそばにプリセットを常に並べる |
| 会話 → 発言 | 1..n | 一覧 | タイムラインの中で、ユーザーの発言と AI の発言を続けて出す |

## ④ に照らした確認

| 観点 | 結果 |
|---|---|
| 最重要コンセプト「食事を撮って記録する」がファーストビューで達成できるか | できる。開いたタイムラインの入力欄の「撮る」で撮れる。カメラを開いて撮るまで2タップかかるので、将来ウィジェットとショートカットで減らす |
| 最重要オブジェクト「食事」を見失わないか | 見失わない。食事はタイムラインの中心に時刻順で並ぶ |
| 能動的な操作は2つ（体重・撮る）だけか | 保てている。入力欄の「撮る」と「体重」だけが、開いたときに操作を求める。体重は、その日が未記録のあいだだけ目立たせる |
| 能動と受動の温度感 | 保てている。会話の入り口はタイムラインに置くが、アドバイスを AI から持ちかけることはしない。アプリから出すのは記録忘れと、目標と1日の目安の知らせだけ（④に合わせた）。料理と材料の修正、傾向の詳細は食事、日のまとめ、目標の中に置く |
| 専用の画面より、小さな機能の組み合わせ | 保てている。会話、知らせ、週の振り返り、目安の変更をタイムラインの出来事として並べ、専用の一覧を作らない。食事の記録と会話は同じ入力欄から行う |

## ⑥ に渡すこと

⑤では経路だけを決めた。次の出し方と位置は⑥で決める。ワイヤーのシートの出し方は、⑥で決めるまでの仮置き。

- 各ビューを通常のビュー（プッシュ遷移）で開くか、シートで開くか。詳細表示はモーダルにしない
- アカウントの入口の位置
- 目標の設定の流れ（手順の数、初期値、飛ばせるもの）
