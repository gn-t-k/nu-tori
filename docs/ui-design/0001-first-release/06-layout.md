# ⑥ レイアウト設計図

⑤ のナビゲーション構造を、iPhone の画面に当てはめる。題材ごとにユーザーと決め、節を足していく。

## フォームファクタと作り方

### 決めたこと

- **フォームファクタ**: iPhone だけ。iPad、Apple Watch、Android は初回リリースに入れない
- **作り方**: Swift（SwiftUI）で、iOS のネイティブアプリとして作る
- **フォント**: システム標準（San Francisco と、日本語はヒラギノ）を使い、Dynamic Type に従う

### 技術者の判断

判断したのは、開発者本人（一人で開発する）。

| 観点 | 判断 |
|---|---|
| 開発体制 | 一人。Web アプリ（React、TypeScript）が専門で、Swift と iOS の開発は初めて。Mac を持っていて、Mac の上を開発の主な場にできる（Mac を主な場にできないなら React Native が向く、というのが調査の分かれ目） |
| 作り方の方針 | プラットフォームに最適化する。HIG に沿って作り、Android 版を出すときは Android に合わせて UI を作り直す |
| Swift を選んだ理由 | 標準の部品を使えば、新しい iOS の見た目にビルドし直すだけで追従できる。ヘルスケアとカメラを Apple の API で直接使える。React Native の利点であるコードの共有は、UI を作り直す方針のもとでは API クライアントなどに限られる（`docs/research/swift-vs-react-native.md`） |
| 技術的な負債と、その手当て | Swift の学習に時間がかかる。はじめは、エージェントが書いたコードを自分で判断しにくい。審査を通さずに直す手段（OTA 更新）がない。これらは、エージェントに検証まで自律的に回させること（Xcode の MCP、MobileBuildMCP、シミュレータの操作、CI）と、TestFlight で身近な人に先に使ってもらうことで補う（`docs/research/agent-ios-verification.md`） |
| 開発環境の制約 | ビルドと画面の確認には Mac が要る。クラウドのエージェント（Linux）では iOS のビルドもシミュレータでの確認もできないので、画面を伴う作業は Mac の上で行う。Mac を閉じているあいだは、クラウドのエージェントで画面以外を進め、macOS の CI で確かめる。ヘルスケアのバックグラウンドの取り込みは実機でしか確かめられないので、人が確かめる |

どのエージェントツールで開発するかは、実装に入るときに決める。

## ペインの割り当て

iPhone は画面が狭く、一度に1つのペインしか出せない。そのため、親を主ペイン、子を従ペインとして、レイアウト3段活用で階層を表す。

- **リスト**: タイムライン。日付で区切った集計ビューを、古い日から今日へ1本に並べる
- **ドリルダウン**: タイムラインから食事・体重・目標・週の振り返りへ、体重から目標へ、食事から栄養の内訳へ、目標から週の振り返りへ、プッシュで潜る。日のまとめから目標・週の振り返りを開くときは、シートを閉じてタイムラインの上に積む
- **スタック**: タブは持たない。根はタイムラインの1つで、潜ったビューはその上に積む
- **シート**: 日のまとめ、アカウント、体重の入力

子が少なく、その場で読めば足りるものは、親のペインの中に並べる（インライン）。潜らないと扱えないものだけを、プッシュで従ペインにする。

| 関連（③） | 親 | 主ペイン（親を見せる場所） | 従ペイン（子を見せる場所） | 子の出し方 |
|---|---|---|---|---|
| アカウント → ユーザー | アカウント | アカウント（シート） | — | ユーザーは属性を持たないので、並べるものはない。アカウントの削除で、ユーザーの記録もまとめて消す |
| ユーザー → 現在の目標 | ユーザー | 日のまとめ（目標の要約） | 目標 | シートを閉じてプッシュ。目標がないときと達成・期限のときは、タイムラインの目標の知らせのカードをその場で広げて目標の設定を進める |
| ユーザー → 過去の目標 | ユーザー | 目標 | 過去の目標の一覧 | 目標の一番下に並べる。期限と結果だけなので、潜らない。ユーザーの目標をまとめて見る場所として、タイムラインではなく目標に置く（③、⑤ の表示パターン） |
| 目標 → 1日の目安 | 目標 | 目標 | 1日の目安の推移 | 目標の中に、推定した消費量と重ねたグラフで示す。今の目安はカードで強調する |
| ユーザー → 体重記録 | ユーザー | タイムライン | 体重の画面 | タイムラインの行に並べ、押すとプッシュで体重の画面へ潜る。直すときは体重の画面の中でその場で直す。入れるときはシート |
| ユーザー → 食事 | ユーザー | タイムライン | 食事 | プッシュ |
| 食事 → 料理 | 食事 | 食事 | 料理の一覧 | 食事の中に並べる |
| 料理 → 材料 | 料理 | 食事（料理の行） | 材料の一覧 | 料理の行の下に並べ、量はその場で直す |
| ユーザー → 会話 | ユーザー | タイムライン | 会話 | タイムラインにその時刻の出来事として並べる |
| 会話 → 発言 | 会話 | タイムライン（会話のまとまり） | 発言 | 会話のまとまりの中に、ユーザーの発言と AI の発言を続けて並べる |

- 料理の栄養の内訳（ビタミン・ミネラルを含む）は、料理の行からプッシュで開く。料理1つで14項目ほどあり、食事の中に広げると、ほかの料理と材料が画面の外に押し出されて読みにくくなる。食事の画面は量を直す場所なので、短く保つ。内訳を見るのは、Mさんのように栄養を細かく確かめたい人に限られる（食事_8）
- 単位ビュー「食事」は、食事の画面と栄養の内訳の画面の2つからなる。⑤ の単位ビューの境界は変えない
- 料理の行の下にその場で広げる案と、プロトタイプで比べて決めた（ブランチ `prototype/0001-nutrition-breakdown` の `docs/ui-design/0001-first-release/prototype-nutrition.html`）。広げる案は現在地が変わらず、材料と栄養を並べて見られるが、差は小さく、食事の画面の短さを取った
- 週の振り返りは、1日の目安の適用期間で区切った集計ビューで、③ の関連には当たらない。タイムラインと目標から、プッシュで開く。日のまとめからは、シートを閉じてプッシュで開く
- 日のまとめは、1日で区切った集計ビューで、③ の関連には当たらない。タイムラインの1日の丸から、シートで開く
- 潜る深さは最大で4段（タイムライン → 体重 → 目標 → 週の振り返り）。ほかは3段まで（タイムライン → 食事 → 栄養の内訳、タイムライン → 目標 → 週の振り返り）。どこからも「戻る」で1段ずつ戻れ、週の振り返りの「その日へ」でタイムラインに戻れる

## タイムラインの並べ方と、1日の丸

ワイヤー: `06-layout/timeline.html`（単位ビュー「タイムライン」「入力欄」「日のまとめ」と、体重の画面）

### 決めたこと

- **並べ方**: 古い日から今日へ並べ、新しいものが下に来る。開くと今日の一番新しい位置にいる。送った文章への AI の発言も、撮った食事も、入力欄のすぐ上に出る
- **ナビゲーションバー**: 標準のナビゲーションバーを使い、題を空にする。タブがなく、根はタイムラインの1つなので、題は位置を知る助けにならない。HIG の Toolbars は、題が冗長なら空にしてよいとしている（`docs/research/hig-toolbar-empty-title.md`）。末尾（右端）にアカウントの入口を置く（「アカウントの入口」）
- **1日の丸の帯**: ナビゲーションバーのすぐ下に固定し、7日分の丸を並べる。習慣トラッカーを兼ねる。帯は画面を切り替えず、日のまとめのシートを開くだけなので、独自のナビゲーションにはしない。スクロールすると、いま見ている日の丸が選ばれた状態になる。横に送ると前の週へ移る
- **1日の丸**: 1本の輪を、その日食べた P・F・C の kcal で色分けし、一周で1日の目安にする。目安を超えた日は、超えたことがわかる印を付ける。目標がないあいだは比べる目安がないので、P・F・C の割合で一周させる。体重を記録した日は、丸の中に印を付ける
- **日のまとめ**: 丸を押すとシートで開く。食事と栄養（大きな丸、kcal と P・F・C。どれも食べた量と1日の目安を並べる）、体重と目標（その日の体重、体重の傾向、目標の要約）、週の振り返り、「タイムラインでこの日を見る」を置く。‹ › で日を送る
- **入力欄**: 下に固定する。左から「撮る」「体重」、書く欄、「送る」。上にプリセットを並べる。その日の体重が未記録のあいだは「体重」を目立たせる
- **書いて送った文章**: 食べたものを書いた文章は食事として記録し、返ってきた食事に「会話として送り直す」を添える。それ以外は会話として答える。食事の時刻は、文章に時刻があればそれを使い、なければ送った時刻にする。時刻は食事の画面で直せる
- **撮っておいた写真**: 写真は送った時刻の位置に出し、食事には撮った時刻を示す。1日の集計は撮った時刻の日に入れる
- **知らせ**: アプリから出すのは、記録忘れ（体重、食事）、目標がないときの「目標を立てる」、目標の達成・期限、1日の目安の変更だけ。記録忘れは iPhone の通知と同じ内容をタイムラインにも出し、体重の知らせの中ではその場で体重を入れられる。食事の知らせは撮っていないことを示し、カードに「撮る」を置く（書いて記録するときは入力欄を使う）。iPhone の通知を押すと、アプリを開いてタイムラインのその知らせの位置に着く（通知_1）

### 答えていない知らせ

目標の知らせ（目標を立てる、次の目標を選ぶ、次の目標を立てる）と体重の知らせは、答えを待っている。答えないまま画面の上へ流れたら、帯の下に1行で示す。

- 押すと、その知らせまでスクロールする
- 知らせに答えるか、目標の知らせの「あとで」を押すと消える
- 知らせが画面に見えているあいだは出さない
- 入力欄の上に固定する案とも比べた。入力欄の上がずっと催促で埋まり、目標を立てる手順を広げると入力欄が押し上げられるので、採らなかった

### 撮るまでの手数

入力欄の「撮る」でカメラを開き、撮る。撮るまで2タップかかる。将来、ウィジェットとショートカットから撮れるようにして減らす（`01-use-cases.md` の「検討して入れなかったもの」）。

終盤ゲートの「④の最重要コンセプトがファーストビュー1アクションで達成できる」は、開いた画面から「撮る」1つで撮影に入れることで満たすと判断する。シャッターを押すことは撮る行為そのもので、画面を探す手数ではない。2タップを受け入れ、将来ウィジェットとショートカットで補うことは、ユーザーと合意した（2026-09-24）。

### 輪の形とアクティビティリング

HIG は、アクティビティリングをムーブ・エクササイズ・スタンド以外に使うことと、真似ることを禁じている。ほかの輪の形の要素は、見分けられるようにすれば置ける（`docs/research/hig-activity-rings.md`）。帯の小さな丸は、曜日のラベルを添え、帯の区切り線と余白でほかの要素と分ける。日のまとめの大きな丸には kcal と P・F・C のラベルを添える。どちらも輪を1本にし、P・F・C の色を使う。見分けられるかは、⑦で見た目を作るときに確かめる。

### プロトタイプ

- `prototype/0001-timeline` の `prototype-timeline.html`: 一番上に要約とファインダーを集めたまま、1日の中を新しい順にするか古い順にするかを比べた。どちらも無理があるとわかった
- `prototype/0001-tabs` の `prototype-tabs.html`: タブで「今日｜タイムライン」「タイムライン｜進み具合」に分ける案を比べた。食事と栄養、体重と目標の情報がばらばらになるので採らなかった
- `prototype/0001-weight-view` の `prototype-weight.html`: タイムラインの体重の行を押したとき、目標の画面へ潜るか、体重の画面へ潜るかを比べた。目標がないと開けないこと、食事との揃い方から、体重の画面を採った
- `prototype/0001-chat-rings` の `prototype-chat-rings.html`: 1日の丸の帯と日のまとめ、アカウントの入口、目標の入口（知らせとして流す、入力欄の上に固定する、流して帯の下に示す）を比べた。右の「目標の状態」で、目標なし・進行中・達成・期限を切り替えられる

## 各ビューの出し方とアカウントの入口

### 決めたこと

ものの詳細へ潜るときはプッシュで開く。短く区切れる作業はシートで開く。HIG の Sheets は、シートを「今の文脈に近い、範囲の狭い作業」に使うものとしている（`docs/research/hig-inline-goal-setup.md`）。⑤ の「⑥ に渡すこと」のとおり、詳細表示はモーダルにしない。`03-frames/` のワイヤーにある戻る・閉じるなどの枠と、操作の置き場（押したときの動き、入力の欄）は ③ での仮置きで、出し方と閉じ方はこの節で、操作の置き場は「全単位ビューのレイアウト」で定める。

| 単位ビュー | 出し方 | 閉じ方 | 理由 |
|---|---|---|---|
| サインイン | 全画面。済んだらタイムラインに置き換え、戻れない | — | サインインが済むまで、ほかに使える画面がない |
| タイムライン | 根。ナビゲーションスタックの一番下 | — | — |
| 食事 | プッシュ | 戻る | 詳細表示。記録の直後に開くときも同じ |
| 日のまとめ | シート（1日の丸から） | 完了 | 1日の数字をまとめて見る、短い作業。‹ › で日を送る。タイムラインの上に重ねるので、どの日を見ているかを見失わない |
| 目標 | プッシュ（日のまとめから開くときは、シートを閉じてから） | 戻る | 詳細表示。知らせから開いたときも、タイムラインの上に積むので、戻るとタイムラインに着く |
| 栄養の内訳 | プッシュ（食事の料理の行から） | 戻る | 詳細表示。単位ビュー「食事」の2つめの画面（「ペインの割り当て」） |
| 週の振り返り | プッシュ（日のまとめから開くときは、シートを閉じてから） | 戻る | 詳細表示。タイムライン、日のまとめ、目標から開く。「その日へ」でタイムラインのその日の位置に戻る |
| 体重の画面 | プッシュ（タイムラインの体重記録の行から） | 戻る | 詳細表示。食事のカードを押すと食事の画面へ潜るのと揃える。押した日の値と「直す」、最近4週の傾向（目標があれば目標体重の線）、目標までの道のり（目標へ進める）、最近の記録を並べる。直すときは、その場で値の欄に変わる |
| 体重の入力 | シート（入力欄の「体重」から） | キャンセル／記録 | 1つの値を入れる、短い作業。体重の知らせの中では、その場で入れられる |
| 入力欄 | タイムラインの下に固定する。シートにしない | — | 撮る、体重、書いて送る、プリセットをまとめて置く。書いて送った文章は、食事の記録か会話かをアプリが読み分ける |
| カメラ（入力欄の「撮る」から） | 全画面 | 閉じる／撮る | ファインダーを大きく見せる必然性がある。撮るとすぐ閉じて、タイムラインに戻る |
| 目標の設定 | 知らせのカードをその場で広げる（「目標の設定の流れ」）。日のまとめと体重の画面から始めるときは、タイムラインに戻って一番下にカードを出す | 閉じる | — |
| アカウント | シート | 完了 | タイムラインの階層の外にある。許可の状態とアカウントの削除を扱う |

- 目標ビューの「目標を切り替える」も、目標ビューの一番上にある現在の目標のカードを、その場で広げる。中身はタイムラインから開くときと同じ
- シートを開いたまま、別のシートを重ねない。アカウントから通知やカメラの設定へは iPhone の設定を開き、ヘルスケアは行き方を文で示すだけなので、シートは重ならない。日のまとめから目標、週の振り返り、目標の設定へ進むときは、シートを閉じてから開く
- ヘルスケアへの書き込みの許可（初めて食事を記録したあと）は、カメラや写真を選ぶ画面を閉じ、タイムラインに戻ってから求める。自前の説明画面は作らない
- アカウントの削除は、アラートで確かめる。消すボタンは破壊的な操作の見た目にし、否定の操作は「キャンセル」1つにする

### アカウントの入口

タイムラインのナビゲーションバーは題を空にする（「タイムラインの並べ方と、1日の丸」）。その末尾（右端）に、人の形のアイコンを置く。すぐ下の1日の丸の帯と並んで見える。ヘルスケアアプリや App Store でアカウントを右上から開き、シートで出すのに合わせた。日のまとめのシートの中に置く案もプロトタイプで比べたが、アカウントは日のまとめと関係がなく、削除や許可を探す人が迷うので採らなかった。これは HIG の本文ではなく Apple のアプリの振る舞いで、実機で確かめる。Apple のアプリは右上に写真や頭文字を出すが、nu-tori は写真を持たないので、人の形のアイコンにする。

### アカウントに置く許可の扱い

ヘルスケアの共有は iPhone の設定とヘルスケアアプリで管理し、アプリの中で変える画面を作らない。読み取りの許可の状態はアプリから分からない（`docs/research/app-permission-settings.md`）。

| 許可 | アカウントに出すもの | 変えるとき |
|---|---|---|
| ヘルスケア | 読み取る種類と書き込む種類。許可の状態は出さない | iPhone の設定かヘルスケアアプリで変えられることを文で示す。アプリから直接開く手段が見当たらないので、ボタンは置かない |
| 通知 | 許可の状態 | iPhone の設定にある、このアプリの通知の設定を開く |
| カメラ | 許可の状態 | iPhone の設定にある、このアプリの設定を開く（カメラの切り替えがそこに出るかは実機で確かめる） |

- アカウントの中で、許可を切り替えるスイッチは作らない
- 書き込みの許可の状態はアプリから分かるが、これも出さない。読み取りの状態が分からないまま書き込みだけを示すと、ヘルスケアとのやりとり全体が許可されているように読めてしまう
- 通知とカメラは開く先が違うので、「iPhone の設定を開く」をそれぞれに置く

## 目標の設定の流れ

### 決めたこと

タイムラインの目標の知らせ（「目標を立てる」「次の目標を選ぶ」）のカードを、その場で広げる。広げたカードの中は1ページに1つの問いで、ページを送って進む。

- **その場で広げる理由**: 画面が変わらないので、ユーザーが自分の現在地を見失わない。閉じてもタイムラインに戻るだけで、不安にならない
- **ページ送りにする理由**: あといくつ手順があるかが見える
- **シートにしない理由**: ヘルスケアの許可は、iPhone がシートとして出す。流れをシートで出すと、その上に許可のシートが重なる。HIG は「シートは一度に1つ」としているが、それがシステムの許可のシートにも及ぶかは書いていない。カードで進めれば、重なり自体が起きない。HIG はシートとカードの優劣を決めていない（`docs/research/hig-inline-goal-setup.md`）

4案をプロトタイプで比べて決めた（後述）。⑤ の単位ビュー表と `03-frames/goal-setup.html` に並ぶ手順とシートの形は、⑤ の「⑥ に渡すこと」のとおり仮置きで、手順と出し方はこの節で定める。

ワイヤー: `06-layout/goal-setup.html`

### 開くところ

- タイムラインの知らせ「目標を立てる」（目標がないとき。使い始めに出す）
- タイムラインの知らせ「次の目標を選ぶ」（期限が来たとき、期限より前に達成したとき）
- タイムラインの知らせ「次の目標を立てる」（期限後に選ばなかったとき）
- 日のまとめの「目標を立てる」「次の目標を選ぶ」「次の目標を立てる」。シートを閉じ、タイムラインの一番下に同じ知らせのカードを出して広げる。途中まで進めていたら、同じページから続ける
- 体重の画面の「目標を立てる」（目標がないとき）。タイムラインまで戻り、日のまとめから開くときと同じく、一番下に知らせのカードを出して広げる
- 目標ビューの「目標を切り替える」（目標ビューの一番上にある、現在の目標のカードを広げる）

期限や達成のときの結果は、⑤ の「目標の状態と入口」のとおりカードに出し、広げるとページ1から始まる。向きを選ぶとその向きの目標案が出るので、「増量・減量・維持のそれぞれについて次の目標を提案する」（S10-2）はこの流れで満たす。目標ビューから開くときも、中身は同じ。

### 手順

| ページ | 問い | 出るとき | 初期値 | 飛ばせるか |
|---|---|---|---|---|
| 1 | 何を目指すか（減量・維持・増量） | いつも | なし | 飛ばせない |
| — | ヘルスケアの許可（iPhone の画面） | 1で選んだ直後。初めて目標を立てるときに、目標の計算に要る種類（身長・生年月日・性別・歩数・体重と、使い始める前の消費量を推定するための食べた栄養）のうち、まだ求めていない種類があるときだけ | — | 許可しなくても先へ進める |
| 2 | 足りない値（身長、生年月日の年、性別、今の体重、活動量） | ヘルスケアから取れない値が1つでもあるとき。足りない項目だけ値の欄にする。目標を立て直すときは、今の体重だけ（その日の記録がなければ） | 体重は、その日の記録がなければ最新の値を薄く示す | 取れた値は聞かない。全部取れたらページごと出ない |
| 3 | 難易度（ゆるめ・標準・ハード） | 減量・増量のとき | 「標準」に「おすすめ」を付ける | 押した時点で目標が決まる。確認のページはない |
| 3 | 今の体重を保つ | 維持のとき | 今の体重、期限なし | 「維持で始める」で決まる |

- 目標案の3枚には、期限と目標体重、1日の目安（kcal）、大変さのひとことを、選ぶ前から書いておく
- 目標案の下に「期限と目標体重を自分で決める」を置く。入れるとその場で1日の目安と大変さを出し、「この目標で始める」で決まる（S2 の Mさん）
- 活動量は、ヘルスケアの歩数が取れれば聞かない。取れなければ「ほぼ座り仕事／立ち仕事が多い／よく動く」から選ぶ
- 生年月日は、手で入れるときは年だけを尋ねる。1日の目安の計算には年単位で足りる。ヘルスケアから取れたときは、日付まで使う
- ページ3の上に、使った値を1行で示す（例: 172cm・35歳・男性・72.4kg・歩数から）。「変える」でページ2を開き直せる。身体データは保存せず、ここで入れ間違いを直す。目標を立て直すときは、推定した消費量と今の体重を示す
- 身体データを使うのは、推定した消費量がまだない、初めて目標を立てるときだけ。見積もった消費量は最初の1日の目安に残り、以後は体重の傾向と食べた量から推定し直すので、目標を立て直すときは身体データを読みも尋ねもしない（③）
- 決まると、カードは決めた目標を示す形に変わる。1日の丸も、この時点から今日の食べた量を1日の目安と比べる形に変わる
- 画面の文言（問いの書き方、ボタンの名前）は⑦で決める

### カードの振る舞い

HIG に照らして守ること。根拠は `docs/research/hig-inline-goal-setup.md`。

- 「閉じる」はどのページでも右上に見せる。閉じても答えは捨てず、確認も出さない。途中の答え（手で入れた身体データを含む）は端末の中だけに持ち、目標が決まった時点で捨てる。サーバーには送らない。閉じたカードは「途中から続ける」になり、開くと同じページから始まる
- 広げる前のカードには「あとで」を置く。押すと、帯の下の知らせ（「答えていない知らせ」）が消える。カードはタイムラインに残り、日のまとめからも始められる（S11 の Mさんのように、選ぶのを急かさない）
- 「戻る」は2ページ目から左下に置き、「閉じる」と見間違えない位置と見た目にする
- 「次へ」は、ページ2で足りない値がそろうまで押せない
- 残りの手順は、右上の「2/3」と押せない点で示す。Page control（押すと先へ飛べる）と Progress indicator（処理の待ち時間を表す）は使わない
- 手順の総数は、その人に要るページの数に合わせる（2か3）
- カードの中で縦にスクロールさせない。広げたときは、カードが見えるところまでタイムラインを自動でスクロールする。値の欄がキーボードに隠れないようにする
- ヘルスケアの許可の前に、自前の説明画面を作らない。何に使うかは、iPhone の許可画面に出る使用目的の文で伝える
- 許可しなかったことを画面で指摘しない（読み取りを拒否されたかはアプリから分からない）。ページ2を出すかどうかは、値が取れたかだけで決める
- 「視差効果を減らす」設定のときは、ページの横移動とカードの広がりをフェードに置き換える。VoiceOver では「何問目／全部で何問」を読み上げる

## 全単位ビューのレイアウト

単位ビューごとに、画面の並びと、直す・消す操作の置き場所を決める。タイムライン、入力欄、日のまとめは「タイムラインの並べ方と、1日の丸」、目標の設定は「目標の設定の流れ」に書いた。

### 食事

ワイヤー: `06-layout/meal.html`

- **並び**: 上から、写真（0枚なら記録した文章）、時刻、合計（kcal と P・F・C）、料理の一覧、料理を足す、食事を消す。料理の行の下に材料を並べる。写真が2枚以上なら横に送る
- **その場で直す**: 直すのはすべて食事の画面の中で行い、別の画面を開かない。押すと直せる値（時刻、料理の名前と量、材料の量）は、見た目で押せるとわかるようにする（見た目は⑦で決める）
  - 料理の名前か量を押すと、その行が値の欄に変わり、名前と量を一緒に直せる。料理の量を直すと、材料の量も同じ割合で変わる（食事_6,12）
  - 材料の量を押すと、その場で値の欄に変わり、数字のキーボードが出る。単位は材料ごとに推定したものを使う（食事_11）
  - 時刻は押すと iOS の日時の選び方で直せる。写真の食事は撮った時刻、文章の食事は文章の中の時刻か送った時刻を初期値にする
  - 直すと、料理と食事の合計、1日の丸、ヘルスケアに書き出した値がすぐ変わる
- **推定した量**: 推定したままの料理の量には「推定」を添え、直すと外す（③の「量の出どころ」）
- **料理を足す・消す**: 「料理を足す」で一番下に名前の欄を出し、名前を入れて足すと量と材料を推定する（食事_13）。料理を消すのは、料理の行を直すときの「この料理を消す」と、行を左へ送る操作の2つ。行を送る操作は VoiceOver ではカスタムアクションで出す（食事_14）
- **空の食事**: 推定中は料理の一覧の場所に「推定しています…」を出す。推定できなかったときは、その旨と「料理の名前を入れると推定する」ことを示し、「料理を足す」を続けて置く（③の多重度 0..n）
- **食事を消す**: 画面の一番下に、破壊的な操作の見た目で置く。iOS の連絡先の「連絡先を削除」と同じ置き方で、ナビゲーションバーにメニューを置かない。押すと画面の下から確かめ、否定の操作は「キャンセル」1つにする。消すとタイムラインに戻る（食事_5）
- **栄養の内訳**: 料理の行の「栄養の内訳 ›」からプッシュで開く。題は料理の名前、戻るは「‹ 食事」。主な栄養、ミネラル、ビタミンの順にまとめて並べる。見るだけで、直すのは食事の画面で行う（食事_8）

### 体重の入力

ワイヤー: `06-layout/weight-input.html`

- **出し方**: 入力欄の「体重」からハーフシートで開く。左上に「キャンセル」、右上に「記録」、題は「体重」
- **初期値**: 前回の値を入れておく。初めてのときはヘルスケアにあった最新の値（S1-3、S3-1）。前回の日付を値の下に添える。前回の値は測った値で、当てずっぽうの値ではない。測らずに「記録」を押せてしまうが、操作を増やさないこと（④の設計思想1）を「測った値だけを受け付ける」（設計思想3）より上に置き、体重の画面で直せるので受け入れる（体重_1,2、S3-1）
- **動かし方**: 値の両側に − と + のステッパーを置く。1回で 0.1 kg 動き、長押しで続けて動く。毎朝の変化は小さいので、多くの朝は数回押して記録するだけで済む。数字を押すと数字のキーボードに変わり、打つと置き換わる（大きく動いた朝や、何日も空いたあと）。キーボードをはじめから出さないので、シートが低く、後ろのタイムラインが見える
- **日時**: 記録した時点にする。シートでは日時を選ばせない。測り忘れた日をあとから埋める操作は置かない（S3-5）
- **1日に1つ**: 今日すでに記録していれば、今日の値を初期値にして開き、記録すると置き換える。ほかの日の値は体重の画面で直す（体重_2）
- **打ち間違い**: 前回と大きく違う値は、シートの中で知らせる。記録は止めない。どれだけ違えば出すかは実装で決める
- **初めてのとき**: 押した直後に、ヘルスケアの体重の読み取りを iPhone の画面で求め、済んでからシートを開く。初めて記録したあとは、シートを閉じてから、通知の許可を iPhone の画面で求める。どちらも自前の説明画面は作らず、シートの上に重ねない（S1-3,4）
- **記録したあと**: シートを閉じ、タイムラインの一番下に体重の行を出す。今日の丸に印を付け、入力欄の「体重」を目立たなくする（S3-4,6）
- **体重の知らせの中**: 知らせのカードに、シートと同じステッパーと「記録」を置き、前回の値を初期値にする。記録すると知らせは答えた形に変わり、帯の下の1行も消える（S3-5）
- **プロトタイプ**: ブランチ `prototype/0001-weight-input` の `docs/ui-design/0001-first-release/prototype-weight-input.html`。数字のキーボード、ステッパー、ホイールで、記録までの操作の数を比べた。ステッパーは、ふつうの朝（前回から −0.2 kg）で4回（開く、− を2回、記録）、キーボードは毎回6回。ホイールは回す回数が少ないが、行き過ぎやすく、VoiceOver で扱いにくいので採らなかった

### 体重の画面

ワイヤー: `06-layout/timeline.html`（最後の図）

- **並び**: 上から、押した日の値（日付、値、手で記録かヘルスケアからか）と「直す」、最近4週の傾向（測った点と傾向の線、目標があれば目標体重の点線）、目標までの道のり（あと何 kg、間に合うペースか、「目標 ›」）、最近の記録
- **直す**: 「直す」を押すと、その場で値の欄に変わり、数字のキーボードが出る。最近の記録の行を押しても、その行がその場で値の欄に変わる。食事の画面の直し方と揃え、別の画面を開かない。直すと傾向の線を引き直す（体重_2）。ヘルスケアから取り込んだ値を直しても、ヘルスケアの値は変えない
- **目標がないとき**: 目標までの道のりの代わりに「目標を立てる」を置く。押すとタイムラインに戻り、一番下に目標の知らせのカードを出して広げる（「目標の設定の流れ」）
- **記録が少ないとき**: 傾向の線は、記録が数日たまるまで引かず、測った点だけを示す。何日で引くかは実装で決める
- **最近の記録**: 新しい順に並べ、最近4週の分で止める。それより前はタイムラインを上へ送って見る

### 週の振り返り

ワイヤー: `06-layout/weekly.html`

- **並び**: 上から、週の区切り（日付と「減量の3週目」）、期限に間に合うペースか、体重（測った点と傾向の線、目標までの道筋の点線）、食べた量（日ごとの棒と1日の目安の線、平均）、P・F・C の1日の平均（目安と並べる）、日ごと、次の週の1日の目安
- **ペースを一番上に**: Tさんが週末に知りたいのは、期限に間に合うかどうか（S8-1）。ペースは傾向の変化と要るペースで示し、日々のブレでは判断しない。間に合わない週も責めず、事実だけを示す。どうすればいいかは、入力欄から尋ねられる（S8-2）
- **記録が少ない週**: 体重の記録が少なく傾向が定まらない週は、ペースを言い切らず、記録の日数を示す。食べた量は記録した日だけで平均し、記録のない日はそうとわかるようにする。どれだけ少なければ言い切らないかは実装で決める
- **日ごと**: 1日の丸、食べた量、体重を1行ずつ並べる。行を押すと、タイムラインのその日の位置に戻る（食事_9）
- **週を送る**: 週の区切りの ‹ › で、前後の週へ送る。日のまとめの ‹ › と揃える
- **次の週の1日の目安**: 値と変わった量、ひとことの理由を示す。詳しい推移は目標の中の1日の目安の推移で見る（目安_5）。週の振り返りから目標へは潜らない（目標から開いたときに行き来が輪になるため）
- **タイムラインでの出し方**: 1日の目安が切り替わる時点に、振り返りのカードを出す。すぐ下に1日の目安の変更の知らせを並べる。目標がないあいだは1日の目安がなく、週の区切りもないので、振り返りのカードを出さない

### 目標

ワイヤー: `06-layout/goal.html`

- **並び**: 上から、今の目標のカード、今の1日の目安、体重の傾向（開始から期限まで、目標までの道筋の点線）、消費量と1日の目安、週の振り返り、過去の目標
- **今の1日の目安**: kcal と P・F・C を並べる。P・F・C の目安はアプリが決め、初回リリースでは直す操作を置かない（たんぱく質は体重から、脂質はカロリーの割合から決め、残りを炭水化物にする。式は実装で決める）
- **今の目標のカード**: 向きと期間、あと何 kg、あと何日、間に合うペースかを示す。進行中は右上に「目標を切り替える」を置く。押すとこのカードをその場で広げ、目標の設定を始める（「目標の設定の流れ」）。選び終えるまで今の目標は続き、決まると前の目標は過去の目標に移る（S9-1）
- **状態で変わるカード**: ⑤の「目標の状態と入口」のとおり、カードの中身を変える
  - 期限前の達成: 届いたことと「次の目標を選ぶ」。選ぶまで今の目標を続けることを添える（S11-1,2）
  - 期限: 結果（開始からの変化、目標との差）と「次の目標を選ぶ」。体重の傾向の見出しを「体重の歩み」にする（S10-1,2）
  - 期限後に選ばなかった: 今の体重を保つ目標（期限なし）と「次の目標を立てる」。前の目標は過去の目標に移る（S10-3）
  - この3つの状態では、カードのボタンが「目標を切り替える」の代わりになる。押すとカードを広げる
- **消費量と1日の目安**: 推定した消費量の線と、1日の目安の階段の線を、1つの kcal のグラフに重ね、2本の間を1日に減らす分（増量では足す分）として示す。消費量が下がると目安も下がることが線で見えるので、目安が変わった理由がわかる（目安_4,5）。表にしないのは、パッと見で変化が頭に入らず、長く使うと行が増え続けるため。グラフは目標の期間に収まる。グラフの週を押すと、その週の値をグラフの上に出す
- **週の振り返り**: 目標には、いまの週の振り返りへの1行を置く。前の週へは、週の振り返りの ‹ › で遡る。長く使ってもページ送りが要らない
- **グラフのプロトタイプ**: ブランチ `prototype/0001-goal-charts` の `docs/ui-design/0001-first-release/prototype-goal-charts.html`。体重、1日の目安、推定した消費量を3つのグラフにする案と比べた。3つだと、目安と消費量を上下に見比べないと理由がわからず、1つめの画面に収まらないので採らなかった
- **過去の目標**: 向き、期間、開始と終わりの体重、結果だけを並べ、潜らない。空なら見出しごと出さない
- **目標がないとき**: 目標の画面は開かない。入口（日のまとめ、体重の画面）には「目標を立てる」を置く

ワイヤー: `06-layout/account.html`

- **並び**: 上から、ヘルスケア（読み取る種類と書き込む種類）、通知、カメラ、プライバシーポリシー、アカウントの削除。iOS の設定と同じ、まとまりごとの一覧にする
- **身体データは置かない**: 身体データは目標の設定の入力で、保存しない（③）。入れ間違いは目標の設定の中で直し、推定した消費量も数週間で体重の傾向から補正される
- **許可**: 「アカウントに置く許可の扱い」のとおり。状態の行と「iPhone の設定を開く」の行を、通知とカメラにそれぞれ置く
- **プライバシーポリシー**: ブラウザで開く。App Store の審査ガイドライン 5.1.1 は、プライバシーポリシーへのリンクをアプリの中の見つけやすい場所に置くよう求めている（本文は実装の前に確かめる）。サインインの画面にも置く
- **アカウントの削除**: 一番下に、破壊的な操作の見た目で置き、消えるものと元に戻せないことを添える。アラートで確かめ、消すとサインインの画面に置き換える（アカウント_2）。消すのは nu-tori の記録（食事、体重、目標、会話）とアカウントで、ヘルスケアに書き込んだ栄養は残す。ヘルスケアのデータはユーザーのもので、ヘルスケアアプリで消せることをアラートで示す。Sign in with Apple のトークンの取り消しは実装で行う
- **省く候補**: カメラの行（撮るときに許可がなければ、その場で知らせて設定へ案内すれば足りる）。許可のまとまり全体（許可_1 は推奨で、どの許可も iPhone の設定から変えられる）

### サインイン

ワイヤー: `06-layout/signin.html`

- **並び**: アプリのアイコンと名前、ひとことの説明、Apple の標準の「Apple でサインイン」ボタン、プライバシーポリシー。ナビゲーションバーは置かない
- **求めるもの**: 名前とメールアドレスは求めない。アカウントの用途はテストユーザーの見分けとサーバーの不正利用防止で（行動シナリオの「決まった前提」）、どちらも使わない。iPhone の画面で共有を選ぶ手間も省ける
- **やめたとき・失敗したとき**: iPhone の画面を閉じてやめたときは何も出さない。失敗したときは、ボタンの上に理由を出し、同じボタンでやり直す
- **済んだあと**: タイムラインに置き換え、戻れない。目標の設定も許可もここでは求めず、目標を立てる知らせと入力欄の「撮る」が待っている（S1-1）
