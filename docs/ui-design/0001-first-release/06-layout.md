# ⑥ レイアウト設計図

⑤ のナビゲーション構造を、iPhone の画面に当てはめる。題材ごとにユーザーと決め、節を足していく。

## ペインの割り当て

iPhone は画面が狭く、一度に1つのペインしか出せない。そのため、親を主ペイン、子を従ペインとして、レイアウト3段活用で階層を表す。

- **リスト**: タイムライン。日付で区切った集計ビューを1本に並べる
- **ドリルダウン**: タイムラインから食事・目標・週の振り返りへ、プッシュで潜る
- **スタック**: タブは持たない。根はタイムラインの1つで、潜ったビューはその上に積む

子が少なく、その場で読めば足りるものは、親のペインの中に並べる（インライン）。潜らないと扱えないものだけを、プッシュで従ペインにする。

| 関連（③） | 主ペイン（親） | 従ペイン（子） | 子の出し方 |
|---|---|---|---|
| アカウント → ユーザー | アカウント（シート） | 身体データ | アカウントの中に並べる。直すときはシートの中でプッシュ |
| ユーザー → 現在の目標 | タイムライン（一番上の要約） | 目標 | プッシュ。目標がないときは、要約の位置のカードをその場で広げて目標の設定を進める |
| ユーザー → 過去の目標 | 目標 | 過去の目標の一覧 | 目標の一番下に並べる。期限と結果だけなので、潜らない |
| 目標 → 1日の目安 | 目標 | 1日の目安の推移 | 目標の中に並べる。今の目安を強調する |
| ユーザー → 体重記録 | タイムライン | 体重記録 | タイムラインの行に並べる。直すときはシート |
| ユーザー → 食事 | タイムライン | 食事 | プッシュ |
| 食事 → 料理 | 食事 | 料理の一覧 | 食事の中に並べる |
| 料理 → 材料 | 食事（料理の行） | 材料の一覧 | 料理の行の下に並べ、量はその場で直す |
| ユーザー → 会話 | タイムライン | 会話 | タイムラインにその時刻の出来事として並べる |
| 会話 → 発言 | タイムライン（会話のまとまり） | 発言 | 会話のまとまりの中に、ユーザーの発言と AI の発言を続けて並べる |

- 料理の栄養の内訳（ビタミン・ミネラルを含む）は、料理の行からプッシュで開く。項目が多く、食事の中に並べると料理と材料が読みにくくなるため
- 週の振り返りは、1日の目安の適用期間で区切った集計ビューで、③ の関連には当たらない。タイムラインと目標から、プッシュで開く
- 潜る深さは最大で3段（タイムライン → 食事 → 栄養の内訳）

## 各ビューの出し方とアカウントの入口

### 決めたこと

ものの詳細へ潜るときはプッシュで開く。短く区切れる作業はシートで開く。HIG の Sheets は、シートを「今の文脈に近い、範囲の狭い作業」に使うものとしている（`docs/research/hig-inline-goal-setup.md`）。⑤ の「⑥ に渡すこと」のとおり、詳細表示はモーダルにしない。`03-frames/` のワイヤーにある戻る・閉じるなどの枠は ③ での仮置きで、出し方と閉じ方はこの節で定める。

| 単位ビュー | 出し方 | 閉じ方 | 理由 |
|---|---|---|---|
| サインイン | 全画面。済んだらタイムラインに置き換え、戻れない | — | サインインが済むまで、ほかに使える画面がない |
| タイムライン | 根。ナビゲーションスタックの一番下 | — | — |
| 食事 | プッシュ | 戻る | 詳細表示。記録の直後に開くときも同じ |
| 目標 | プッシュ | 戻る | 詳細表示。通知から開いたときも、タイムラインの上に積むので、戻るとタイムラインに着く |
| 週の振り返り | プッシュ | 戻る | 詳細表示。タイムラインからも目標からも開く。「その日へ」でタイムラインのその日の位置に戻る |
| 体重（今日の入力） | タイムラインの入力欄にその場で入れる | — | 毎朝の入力で、シートを開かせない |
| 体重（記録済みの分の修正） | シート | キャンセル／記録 | 1つの値を直す、短い作業 |
| 文章で記録 | シート | キャンセル／記録 | 新しく作る、短い作業 |
| 会話 | タイムラインの下に固定した入力欄。シートにしない | — | AI の発言は、タイムラインにその時刻の出来事として並ぶ。プリセットは入力欄のそばに並べる |
| 目標の設定 | カードをその場で広げる（「目標の設定の流れ」） | 閉じる | — |
| アカウント | シート | 完了 | タイムラインの階層の外にある。身体データとアカウントを扱う |

- 目標ビューの「目標を切り替える」も、目標ビューの一番上にある現在の目標のカードを、その場で広げる。中身はタイムラインから開くときと同じ
- シートを開いたまま、別のシートを重ねない。アカウントから通知やカメラの設定へは iPhone の設定を開き、ヘルスケアは行き方を文で示すだけなので、シートは重ならない
- ヘルスケアへの書き込みの許可（初めて食事を記録したあと）は、文章で記録や写真を選ぶ画面を閉じ、タイムラインに戻ってから求める。自前の説明画面は作らない
- アカウントの中で身体データを直すときは、アカウントのシートの中でプッシュする
- アカウントの削除は、アラートで確かめる。消すボタンは破壊的な操作の見た目にし、否定の操作は「キャンセル」1つにする

### アカウントの入口

タイムラインのナビゲーションバーの右上に、人の形のアイコンを置く。ヘルスケアアプリや App Store でアカウントを右上から開き、シートで出すのに合わせた。これは HIG の本文ではなく Apple のアプリの振る舞いで、実機で確かめる。Apple のアプリは右上に写真や頭文字を出すが、nu-tori は写真を持たないので、人の形のアイコンにする。

### アカウントに置く許可の扱い

ヘルスケアの共有は iPhone の設定とヘルスケアアプリで管理し、アプリの中で変える画面を作らない。読み取りの許可の状態はアプリから分からない（`docs/research/app-permission-settings.md`）。

| 許可 | アカウントに出すもの | 変えるとき |
|---|---|---|
| ヘルスケア | 読み取る種類と書き込む種類。許可の状態は出さない | iPhone の設定かヘルスケアアプリで変えられることを文で示す。アプリから直接開く手段が見当たらないので、ボタンは置かない |
| 通知 | 許可の状態 | iPhone の設定にある、このアプリの通知の設定を開く |
| カメラ | 許可の状態 | iPhone の設定にある、このアプリの設定を開く（カメラの切り替えがそこに出るかは実機で確かめる） |

- アカウントの中で、許可を切り替えるスイッチは作らない
- 書き込みの許可の状態はアプリから分かるが、これも出さない。読み取りの状態が分からないまま書き込みだけを示すと、ヘルスケアとのやりとり全体が許可されているように読めてしまう
- 通知とカメラは開く先が違うので、「iPhone の設定を開く」をそれぞれに置く

## 目標の設定の流れ

### 決めたこと

タイムラインの一番上の「目標を立てる」を、その場で広げる。広げたカードの中は1ページに1つの問いで、ページを送って進む。

- **その場で広げる理由**: 画面が変わらないので、ユーザーが自分の現在地を見失わない。閉じてもタイムラインに戻るだけで、不安にならない
- **ページ送りにする理由**: あといくつ手順があるかが見える
- **シートにしない理由**: ヘルスケアの許可は、iPhone がシートとして出す。流れをシートで出すと、その上に許可のシートが重なる。HIG は「シートは一度に1つ」としているが、それがシステムの許可のシートにも及ぶかは書いていない。カードで進めれば、重なり自体が起きない。HIG はシートとカードの優劣を決めていない（`docs/research/hig-inline-goal-setup.md`）

4案をプロトタイプで比べて決めた（後述）。⑤ の単位ビュー表と `03-frames/goal-setup.html` に並ぶ手順とシートの形は、⑤ の「⑥ に渡すこと」のとおり仮置きで、手順と出し方はこの節で定める。

ワイヤー: `06-layout/goal-setup.html`

### 開くところ

- タイムラインの「目標を立てる」（目標がないとき）
- タイムラインの「次の目標を選ぶ」（期限が来たとき、期限より前に達成したとき）
- タイムラインの「次の目標を立てる」（期限後に選ばなかったとき）
- 目標ビューの「目標を切り替える」（目標ビューの一番上にある、現在の目標のカードを広げる）

タイムラインからは、一番上にある同じカードを広げる。期限や達成のときの結果は、⑤ の「目標の状態と入口」のとおりカードに出し、広げるとページ1から始まる。向きを選ぶとその向きの目標案が出るので、「増量・減量・維持のそれぞれについて次の目標を提案する」（S10-2）はこの流れで満たす。目標ビューから開くときも、中身は同じ。

### 手順

| ページ | 問い | 出るとき | 初期値 | 飛ばせるか |
|---|---|---|---|---|
| 1 | 何を目指すか（減量・維持・増量） | いつも | なし | 飛ばせない |
| — | ヘルスケアの許可（iPhone の画面） | 1で選んだ直後。目標の計算に要る種類（身長・生年月日・性別・歩数・体重）のうち、まだ求めていない種類があるときだけ | — | 許可しなくても先へ進める |
| 2 | 足りない値（身長、生年月日の年、性別、今の体重、活動量） | ヘルスケアから取れない値が1つでもあるとき。足りない項目だけ入力欄にする | 体重は、その日の記録がなければ最新の値を薄く示す | 取れた値は聞かない。全部取れたらページごと出ない |
| 3 | 難易度（ゆるめ・標準・ハード） | 減量・増量のとき | 「標準」に「おすすめ」を付ける | 押した時点で目標が決まる。確認のページはない |
| 3 | 今の体重を保つ | 維持のとき | 今の体重、期限なし | 「維持で始める」で決まる |

- 目標案の3枚には、期限と目標体重、1日の目安（kcal）、大変さのひとことを、選ぶ前から書いておく
- 目標案の下に「期限と目標体重を自分で決める」を置く。入れるとその場で1日の目安と大変さを出し、「この目標で始める」で決まる（S2 の Mさん）
- 活動量は、ヘルスケアの歩数が取れれば聞かない。取れなければ「ほぼ座り仕事／立ち仕事が多い／よく動く」から選ぶ
- 生年月日は、手で入れるときは年だけを尋ねる。1日の目安の計算には年単位で足りる。ヘルスケアから取れたときは、日付まで使う
- ページ3の上に、使った値を1行で示す（例: 172cm・35歳・男性・72.4kg・歩数から）。「変える」でページ2を開き直せる
- 決まると、カードは目標の要約（あと何 kg、あと何日、間に合うペースか）に変わる。タイムラインの1日の目安も、この時点から今日の食べた量と比べ始める
- 画面の文言（問いの書き方、ボタンの名前）は⑦で決める

### カードの振る舞い

HIG に照らして守ること。根拠は `docs/research/hig-inline-goal-setup.md`。

- 「閉じる」はどのページでも右上に見せる。閉じても答えは捨てず、確認も出さない。閉じたカードは「途中から続ける」になり、開くと同じページから始まる
- 「戻る」は2ページ目から左下に置き、「閉じる」と見間違えない位置と見た目にする
- 「次へ」は、ページ2で足りない値がそろうまで押せない
- 残りの手順は、右上の「2/3」と押せない点で示す。Page control（押すと先へ飛べる）と Progress indicator（処理の待ち時間を表す）は使わない
- 手順の総数は、その人に要るページの数に合わせる（2か3）
- カードの中で縦にスクロールさせない。広げたときは、カードが見えるところまでタイムラインを自動でスクロールする。入力欄がキーボードに隠れないようにする
- ヘルスケアの許可の前に、自前の説明画面を作らない。何に使うかは、iPhone の許可画面に出る使用目的の文で伝える
- 許可しなかったことを画面で指摘しない（読み取りを拒否されたかはアプリから分からない）。ページ2を出すかどうかは、値が取れたかだけで決める
- 「視差効果を減らす」設定のときは、ページの横移動とカードの広がりをフェードに置き換える。VoiceOver では「何問目／全部で何問」を読み上げる

### プロトタイプ

- ブランチ `prototype/0001-goal-setup` の `docs/ui-design/0001-first-release/prototype-goal-setup.html`
- 比べた4案: A（1枚のシート、答えると次が現れる）、B（ページ送りのシート）、C（タイムラインの中で広げる）、D（C の中を B のページ送りにする）。D を採った
- 右の「条件」でヘルスケアの許可・中身、歩数、今朝の体重を切り替え、Tさんと Mさんの流れを確かめられる
