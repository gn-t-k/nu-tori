## 1. 提供したいユーザー体験

**栄養を知らなくても、測って撮るだけで、体が目標に近づいていく手応えを持てるようになって欲しい。**

- Tさんには、2か月後に間に合いそうかが、考えなくてもわかるようになって欲しい
- Mさんには、今より少ない手間で、今と同じ精度の管理ができるようになって欲しい

## 2. 設計思想

トレードオフが起きたときは、上にあるものを取る。

1. **ユーザーの操作を増やさない。** 求める操作は「朝に体重を入れる」と「食べるときに撮る」の2つだけ。精度を上げる操作は、いつでもできるが、しなくてよい。操作を1つ増やすくらいなら、推定の精度が少し下がるほうを取る
2. **先回りして気を利かせる。** システムが知りうること（ヘルスケアの値、いつもの時刻、前日の値、以前の修正）は、ユーザーに尋ねる前に使う。尋ねるときは、初期値を入れた状態で尋ねる
3. **値の確かさに応じて受け付け方を変える。** 厳密に測れる値（体重）は測った値だけを受け付ける。測りにくい値（食事の量・栄養）は当てずっぽうでも受け付け、あとから直せる
4. **仕組みを言い訳にしない。** 画面に「AI」という言葉を出さない。どんな技術で推定しているかはシステムの都合で、ユーザーの目的とは関係ない。「間違うかもしれない」という言い訳をせず、推定は可能な限り正確にする。確定した値ではなく推定であることは、読み込み中の表現や値の候補の出し方で伝える
5. **求められていないことは言わない。** アドバイスは尋ねられたときだけ出す。知らせは、記録を忘れていそうなとき、目標がまだないとき、目標に届いたとき・期限が来たとき、1日の目安が変わったときだけ出す。淡々と記録したい人の邪魔をしない
6. **モードレス。** 撮ったあとの確認、目標案の選択、量の修正など、どの操作も途中でやめられ、あとからやり直せる。確認を済ませないと次に進めない作りにしない。起動直後に長い設定も求めず、目標はユーザーが自分のタイミングで立てる
7. **専用の画面より、小さな機能の組み合わせ。** 特定の作業に特化した複雑な専用画面は作らず、汎用的な小さな機能を組み合わせて自由に使えるようにする。開発者の想定を超えた使い方が生まれやすく、専用画面に入る導線がいらないので画面もすっきりする
8. **拡張性。** 課金、他アプリとの連携、写真以外の記録方法を、今の構造を壊さずに足せるようにしておく

## 3. 何をするものか（できること）

| できること | ぶら下がるタスク（`02-tasks.md`） |
|---|---|
| **食事を撮って記録する**（最重要） | 食事を撮る、撮っておいた写真を選ぶ、撮り忘れた食事を文章で入れる、食事の時刻を直す、記録した食事を消す |
| 朝の体重を記録する | 今の体重を入れる（その日の体重がまだないときだけ）、朝の体重を入れる、記録した体重を直す |
| 記録した食事を直して精度を上げる | 料理の量を直す、材料の量を直す、料理の名前を直す、料理を足す、料理を消す、料理の栄養の内訳を開く |
| 体重と食事の傾向を見る | 記録の続き具合を見る、体重の推移を開く、日付を選んでその日の食事を開く、週の振り返りを開く、目安の変更の理由を開く |
| 記録を踏まえて AI と話す | 書いて送る、プリセットを選ぶ、食事として読まれた文章を会話として送り直す |
| 目標を立てる・切り替える | 目標を立てる入口を押す、増量か減量か維持かを選ぶ、欠けた身体データを入れる、目標案を選ぶ、期限と目標体重を自分で入れる |
| はじめる・やめる | Sign in with Apple でサインインする、ヘルスケアの読み取りを許可する、ヘルスケアへの書き込みを許可する、通知を許可する、許可を確かめる、アカウントを消す |

## 最重要

- **最重要タスク**: 食事を撮る
- **最重要オブジェクト**: 食事

理由: 体重はシステムが傾向をならして扱えるので、数日抜けても目安の調整は続く。一方、食事は撮り逃すとその日の摂取量が欠け、消費量の推定と1日の目安の両方が狂う。また「撮る」は1日に何度も起きる操作で、手間の差がいちばん効く。

優先度（`01-use-cases.md` の必須・推奨とあわせて）:

1. 食事を撮る（食事_1,2）
2. 朝の体重を記録する（体重_1）
3. 今日食べた量を1日の目安と比べる（カロリーと PFC それぞれ。減量では超えないように、増量では届くように読む）
4. 傾向を見る、AI と話す、記録した食事を直す
5. 目標を立てる・切り替える（頻度は低い。立てるタイミングはユーザーが選ぶ）

## 習慣化を支えるもの

アドバイスは尋ねられたときだけ出すので、習慣化は次の4つで支える。

- **手間がほぼゼロであること**: 開いたら、下の撮るボタンからすぐ撮れる。体重は前日の値が入った状態で待っている
- **手応えが見えること**: 体重は日々のブレではなく傾向の線で見せる。週の振り返りで、期限に間に合うペースかを伝える
- **続いていることが見えること**: 体重を記録した日と食事を記録した日を、習慣トラッカー（1日の丸の帯）でいつも見せる。空きを作りたくない気持ちが、抜けのない記録を後押しする。帯の置き場と丸の描き方は `06-layout.md` の「タイムラインの並べ方と、1日の丸」
- **忘れたときだけ知らせること**: いつもの時刻を過ぎても記録がないときだけ、iPhone に通知し、タイムラインにも知らせを出す

## 能動と受動の温度感

- ユーザーが能動的にする操作は2つ（体重・撮る）だけ。それ以外の情報（1日の目安との比較、目安の変更）は、アプリを開けば受動的に目に入る置き方にする。傾向の置き場は `05-navigation.md`
- AI との会話の入り口（入力欄とプリセット）はタイムラインに置くが、アドバイスを AI から持ちかけることはしない
- 料理と材料の修正、傾向の詳細は、能動的に取りに行く人だけが辿る奥の階層に置く

## 4. コンセプトイメージ

捨てる前提の落書き。開いてすぐ撮れること、1日の目安との比較と続いてきた日が一目でわかることだけを表している。画面どうしのつながり（タブなど）は⑤で決めるので、ここには描かない。

```
┌───────────────────────────┐
│ ◔ ◕ ◕ ◑ ◕ ◕ ◔        [人] │  ← 1日の丸（食べた量と体重）を日ごとに
│ ───────────────────────── │
│ 07:12 [写真]               │
│       おにぎり ほか  420kcal │
│ 09:00 今日の体重がまだです    │  ← 忘れたときだけの知らせ
│       [ 72.4 ] kg  記録     │
│ 12:30 [写真]               │
│       唐揚げ弁当     780kcal │
│ ───────────────────────── │
│ [撮る][体重] 書いて送る…  [送る]│  ← 撮るも体重もここから
└───────────────────────────┘
```

起動時の画面: S3-1（開いてすぐ体重を入れる）と S4-1（開いてすぐ撮る）は、どちらも「開いた瞬間」を取り合う。撮るも体重も、画面の下の入力欄のボタンから始める。その日の体重が未記録のあいだは、体重のボタンを目立たせる。入力欄の並びと撮るまでの手数は `06-layout.md` の「タイムラインの並べ方と、1日の丸」と「撮るまでの手数」
