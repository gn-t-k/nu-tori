## キー決定

- 最重要コンセプト: 食事を撮って記録する（最重要タスク「食事を撮る」、最重要オブジェクト「食事」）
- キーオブジェクト: 食事、日、体重記録、1日の目安、目標
- ナビの根: 今日（日の詳細）。グローバルナビは 今日／推移／相談 の3タブ
- 食事は 料理 → 材料（食材・調味料）の構造で持つ。推定の精度は事前に検証せず、リリース後に上げる（理由は `03-concept-model.md`）
- 対象フォームファクタ: iPhone（初回リリース）
- ユーザーに求める操作は「毎朝の体重の入力」と「食事の写真を撮る」の2つだけ
- 初期データはヘルスケアなど iPhone にあるデータを最大限使う
- 量などの精度はあとから任意で上げられる。撮った食事は確認せずに食べ始めてよい
- 消費量は MacroFactor と同じく、体重の傾向と食べた量から推定する。運動データは入れない
- AI のアドバイスは尋ねられたときだけ出す（自由な質問とプリセット）。記録だけしたい人の邪魔をしない
- 厳密に測れる値（体重）は測った値だけ、測りにくい値（食事の量・栄養）は当てずっぽうでも受け付ける
- 他のアプリとの連携はヘルスケアを介して行う
- はじめに Sign in with Apple でサインインする
- 1日の食事の回数を決めつけない。食事区分（朝食・昼食・夕食）は設けない
- 1日の目安は1週間ごとに調整する
- 専用の画面より、汎用的な小さな機能の組み合わせで自由に使える画面にする
- 体重を記録した日と食事を撮った日を GitHub の草のようなマスで見せ、記録を続けたくなるようにする
- 起動時は今日のビューの上にファインダーを置く。その日の体重が未記録のあいだだけ、体重の入力欄を目立たせる

## 出荷後の検証

- **写真からの推定の精度**: 1回で推定する方式と、段階的に推定する方式（料理 → 材料 → 食品データベース）を比べる。正解は、市販品のパッケージ表示、栄養価を公開しているチェーン店、量って作った自炊（日本食品標準成分表で計算）の3種類で約30食用意する。カロリーとタンパク質の誤差の率に加えて、同じ写真を繰り返し推定したときのばらつきを重く見る（一定の偏りは、体重の傾向から消費量を推定し直す仕組みが吸収するため）
