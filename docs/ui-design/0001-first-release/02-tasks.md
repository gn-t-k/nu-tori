## 分岐条件メモ

- **ヘルスケアの許可**: 許可しない → 身体データはすべて手で入れる。体重の取り込み（体重_3）は働かない
- **身体データの欠け**: 欠けた項目だけを尋ねる。すべてそろっていれば尋ねない
- **体重の新しさ**: 【仮置き】ヘルスケアの体重が7日より古い → 今の体重を尋ねる
- **活動量**: 歩数が取れる → 歩数から見積もる。取れない → 3択で尋ねる
- **朝の体重**: その日の体重がヘルスケアから入った → 入力欄を出さない。入っていない → いつも記録している時刻を過ぎたら1回だけ知らせる（いつもの時刻がまだわからないうちは【仮置き】朝7時）。それでも入らなければ空欄のまま。当てずっぽうの値は受け付けない
- **使い始める前のデータ**: ヘルスケアに過去の体重と食事量が十分ある → 使い始めた日から消費量を推定する。無い → 歩数か3択の活動量から見積もる
- **食事の記録手段**: 撮れた → 写真。撮れなかった → 文章
- **食後のひとこと**: 毎食後に出す。今日のここまでが目安から外れている（食べすぎ、PFC の偏り）→ 次の食事の提案を添える。1日の食事の回数は決めつけないので、1日のまとめは食後ではなく翌朝に出す
- **前日のまとめ**: 朝の体重が記録されたら出す。【仮置き】体重の記録がない日は、その日はじめてアプリを開いたときに出す
- **目標の期限**: 期限の日に結果を伝え、増量・減量・維持のそれぞれについて次の目標を提案する
- **1日の目安の調整**: 【仮置き】使い始めて7日未満、または直近の体重の記録が少ない → 調整を見送る。ヘルスケアに過去のデータが十分ある人（目安_6）は初日から調整できる
- **目標の切り替え**: 新しい目標を保存しても、前の目標は消さずに記録として残す。履歴を画面に出すかは③以降で決める

## Delete の判定

- 食事の削除（食事_5）は、間違えて撮った記録を消す操作。メンタルモデルは「なかったことにする」なので D とする。誤操作に備えた取り消しは⑦で扱う
- 目標の切り替えは、前の目標を残したまま新しい目標を作るので C とする
- アカウントの削除（アカウント_2）は、記録も含めて復元できない形で消すので D とする。App Store の審査では、アカウントを作れるアプリにはアプリ内で削除する手段が求められる
