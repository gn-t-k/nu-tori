## 分岐条件メモ

- **ヘルスケアの読み取りの許可**: 初めて体重を入れるとき（体重を読む許可）と、目標を立てるとき（向きを選んだ直後。身長・生年月日・性別・歩数のうち、まだ求めていない種類の許可）に求める。許可しない → 身体データはすべて手で入れる。体重の取り込み（体重_3）は働かない
- **ヘルスケアへの書き込みの許可**: 初めて食事を記録したあと（撮る・写真を選ぶ・文章で記録のどれでも）に求める。許可しない → 栄養はヘルスケアに書き込まない。nu-tori の中の記録はそのまま使える
- **身体データの欠け**: 欠けた項目だけを尋ねる。すべてそろっていれば尋ねない
- **初回の体重**: 初めて体重を入れるときは、ヘルスケアにあった体重を古くても初期値として入れておく。目標を立てるときにその日の体重がまだなければ、今の体重を尋ねる
- **活動量**: 歩数が取れる → 歩数から見積もる。取れない → 3択で尋ねる
- **朝の体重**: その日の体重がヘルスケアから入った → 入力欄を出さない。入っていない → いつも記録している時刻を過ぎたら1回だけ知らせる（いつもの時刻がまだわからないうちは朝7時）。それでも入らなければ空欄のまま。当てずっぽうの値は受け付けない
- **使い始める前のデータ**: ヘルスケアに過去の体重と食事量が十分ある → 使い始めた日から消費量を推定する。無い → 歩数か3択の活動量から見積もる
- **目標の有無**: 目標がない → タイムラインは食べた量だけを出し、1日の目安とは比べない。目標を立てる前の体重と食事も、消費量の推定に使う
- **通知の許可**: 初めて体重を記録したあとに求める
- **食事の記録手段**: 撮れた → 写真。撮れなかった → 文章
- **AI の答え**: ユーザーが尋ねたときだけ作る。自動では出さない
- **目標の期限**: 期限の日に結果を伝え、増量・減量・維持のそれぞれについて次の目標を提案する。選ばれなければ、今の体重を保つ目標（期限なし）を作って続ける
- **期限より前の達成**: 日々のブレではなく傾向の線が目標体重に届いたら達成とみなす。伝えて次の目標を提案し、選ばれるまで今の目標を続ける
- **1日の目安の調整**: 1週間ごとに調整する。使い始めて7日未満、または直近の体重の記録が少ない → その週の調整を見送る。ヘルスケアに過去のデータが十分ある人（目安_6）は初日から調整できる
- **目標の切り替え**: 新しい目標を保存しても、前の目標は消さずに記録として残す。過去の目標は目標ビューの一番下に並べる（`05-navigation.md`）

## Delete の判定

- 料理の削除（食事_14）は、推定が余計に拾った料理を取り除く操作。「なかったことにする」ので D とする
- 食事の削除（食事_5）は、間違えて撮った記録を消す操作。メンタルモデルは「なかったことにする」なので D とする。誤操作に備えた取り消しは⑦で扱う
- 目標の切り替えは、前の目標を残したまま新しい目標を作るので C とする
- アカウントの削除（アカウント_2）は、記録も含めて復元できない形で消すので D とする。App Store の審査では、アカウントを作れるアプリにはアプリ内で削除する手段が求められる
