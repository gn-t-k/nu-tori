# ⑦ 表現設計

⑥ のレイアウトに、操作のしかたと見た目を与える。単位ビュー1つを1つのコンポーネントにし、`<名前>/index.html` に置く。どれも先頭行に `<!-- @dsCard group="Views" -->` を持ち、Claude Design の design-system プロジェクトに1つずつ同期できる。共通の見た目は `_base.css`、1日の丸の描き方は `_ring.js` にある。

## コンポーネント

| 単位ビュー | ファイル | 並べた状態 |
|---|---|---|
| サインイン | `signin/index.html` | 初め、失敗したとき |
| タイムライン | `timeline/index.html` | 開いたところ、答えていない知らせ、体重の知らせと撮った直後、週の区切りと書いて送った食事、目標がないとき、食事の知らせ、目標に届いたとき |
| 入力欄 | `composer/index.html` | ふだん、今日の体重がまだ、書いているとき、カメラ |
| 体重 | `weight/index.html` | 体重の画面、その場で直す、目標がないとき、体重の入力（ふだん、キーボード、打ち間違い） |
| 食事 | `meal/index.html` | 食事の画面、料理を直す、材料の量を直す、推定中、推定できない、行を左へ送る、食事を削除、栄養の内訳 |
| 日のまとめ | `day-summary/index.html` | 目標あり、目標がないとき、目標に届いた日 |
| 週の振り返り | `weekly/index.html` | ふだんの週、記録が少ない週 |
| 目標 | `goal/index.html` | 進行中、期限前の達成、期限、期限後に選ばなかった |
| 目標の設定 | `goal-setup/index.html` | 閉じたカード、何を目指すか、足りない値、目標案、自分で決める、決まったあと |
| アカウント | `account/index.html` | 一覧、アカウントの削除のアラート |

## インタラクション

### 操作のしかた

| 操作 | 使うところ | 決めたこと |
|---|---|---|
| 押す | すべて | 押して潜れる行には › を付ける。押してその場で直せる値は、アクセントの色で書く（iOS の編集できる値と同じ） |
| 左へ送る | 食事の料理の行 | 送ると「削除」が出て、送りきると消える。確かめは出さない。VoiceOver ではカスタムアクション「削除」で出す |
| 長押し | ステッパーの − と + | 押しているあいだ、0.1 kg ずつ続けて動く |
| 横に送る | 1日の丸の帯、食事の写真 | 帯は前の週へ、写真は次の写真へ移る |
| 縦に送る | タイムライン、各画面 | タイムラインは下の端（今日の一番新しい位置）から始まる。上へ送ると古い日へ遡り、帯の選ばれた丸が変わる |
| 下へ引く | シート | シートを閉じる。体重の入力は、値を動かしたあとは下へ引いても閉じず、「記録」か「キャンセル」で閉じる（確かめのダイアログは出さない） |
| 文字を入れる | 入力欄、その場で直す値の欄、目標の設定の値の欄 | 数の値は数字のキーボードを出す。入力欄は1行から始まり、書くと5行まで伸びる。「送る」は文字を入れたときだけ、欄の右端に丸い矢印で出す（iOS のメッセージと同じ） |

- **元に戻す**: 取り消しとやり直しの操作は置かない。直した値はいつでも直し直せる。削除すると戻せないもの（食事、アカウント）は、削除する前に確かめる。料理は確かめずに削除するが、「料理を足す」で足し直せる
- **手応え**: 記録したとき、撮ったとき、目標が決まったときに、iPhone の触覚で軽く知らせる。値を直すと、合計・1日の丸・グラフがその場で動いて変わる（どちらも「標準の部品で作るもの」）
- **待つとき**: 推定中は、その食事のカードに回る印と「推定しています…」を出す。画面全体をふさがない。推定を待たずにほかの操作ができる

### モード

原則はモードレス。ダイアログは、戻せない操作を確かめるときにしか出さない。

| モード | 出るところ | 抜け方 |
|---|---|---|
| シート（日のまとめ、体重の入力、アカウント） | タイムラインの上 | 完了、キャンセル、下へ引く |
| 全画面（カメラ） | 入力欄の「撮る」、食事の知らせの「撮る」 | 閉じる、撮る |
| その場で直す値の欄 | 食事、体重の画面 | キーボードの「完了」、ほかを押す |
| 広げた目標の設定のカード | タイムライン、目標 | 閉じる（途中の答えは残す）、目標が決まる |
| 確かめ（アクションシート、アラート） | 食事を削除、アカウントを削除 | 削除、キャンセル |
| iPhone の許可の画面 | 目標の設定、体重の入力、食事の記録のあと、初めて「撮る」を押したとき | 許可する、許可しない |
| 日時を選ぶ（iOS の日時の選び方） | 食事の時刻 | ほかを押す |
| iPhone の写真を選ぶ画面 | カメラの「写真を選ぶ」 | 選ぶ、キャンセル |

- **入れ子は最大2階層**: 2階層になるのは、広げた目標の設定のカードの上のヘルスケアの許可の画面、アカウントのシートの上の削除のアラート、カメラの上の写真を選ぶ画面の3つ。ほかは1階層。カメラの許可はカメラを開く前に出すので、カメラと重ならない
- **ダイアログにしないもの**: 体重の打ち間違い（シートの中に1行）、推定できなかった食事（カードの中）、サインインの失敗（ボタンの上）、知らせ（タイムラインの出来事）は、どれも画面を覆わずその場で知らせる
- **戻る**: iOS の標準どおり、戻るボタンには前の画面の題を出す。タイムラインから潜ると「‹ 9月24日（木）」のように、その日の日付になる
- **名詞から始める**: 開いた画面はタイムライン（食事、体重、会話）で、動詞の見出しやタブはない。直す・消すは、食事や体重を開いてから選ぶ。入力欄の「撮る」と「体重」はカメラと体重計のアイコンだけで示し、VoiceOver では「撮る」「体重」と読む
- **否定の操作は1つ**: 確かめのアクションシートとアラートは、否定の操作を「キャンセル」1つにし、バツは置かない。体重の入力のシートも「キャンセル」と「記録」だけにする。目標の設定のカードとカメラは、文字の「閉じる」1つにする

## ルック&フィール

iOS の標準の見た目をそのまま使う。部品は SwiftUI の標準、色は P・F・C を除いてシステムの色、アイコンは SF Symbols。新しい iOS にビルドし直すだけで見た目が追従する（`06-layout.md` の「技術者の判断」）。色の根拠は `docs/research/pfc-colors.md`、比べた案はブランチ `prototype/0001-look-and-feel` の `docs/ui-design/0001-first-release/prototype-look.html` にある。

### 色

| 役割 | ライト | ダーク | 実装 |
|---|---|---|---|
| アクセント（押せるもの、編集できる値） | `#6155F5` | `#6D7CFF` | `Color.accentColor`（systemIndigo） |
| 地 | `#F2F2F7` | `#000000` | systemGroupedBackground |
| カード、一覧 | `#FFFFFF` | `#1C1C1E` | secondarySystemGroupedBackground |
| 文字 | label、secondaryLabel、tertiaryLabel | 同左 | システムの色 |
| 破壊的な操作 | `#FF383C` | `#FF4245` | `role: .destructive`（systemRed） |
| P（たんぱく質） | `#F07F1A` | `#E8903A` | アセットカタログの色 |
| F（脂質） | `#15803D` | `#228C48` | アセットカタログの色 |
| C（炭水化物） | `#2C7BE5` | `#4290F4` | アセットカタログの色 |

- **アクセント**: systemIndigo。システムの色のうち、白の地で 4.5:1 を超える（5.09:1）のは systemIndigo だけで、小さい文字のリンクや編集できる値にも使える。C の青と紛れない
- **P・F・C の色相**: P オレンジ・F 緑・C 青。FoodNoms と同じ色相。食事管理アプリの間に決まった配色はない（`docs/research/pfc-colors.md`）
- **P・F・C の値**: システムの色（systemOrange・systemGreen）のままでは、1型・2型の色覚で P と F が近く見える。P は systemOrange より明るく、F は systemGreen より暗くし、明るさの差で見分ける。3色のどの組も、色覚の型を問わず見分けられる（dataviz の validate_palette で、ライトとダークの両方の地に対して全組を確かめた）
- **ラベルを添える**: P のオレンジは白の地で 2.6:1 で、グラフの印の目安の 3:1 に届かない。色だけで示さず、いつも「P」「F」「C」か栄養の名前を添える
- **コントラストを上げる**: P・F・C はシステムの色ではないので、アセットカタログの High Contrast の版を用意する（ライトは白の地で 4.5:1 以上になる濃さ）
- **アクティビティリングと見分ける**: オレンジ・緑・青はアクティビティリング（赤・黄緑・水色）に近いので、形とラベルで見分ける。輪は1本で、色の間にすき間を空け、黒い地に光る見た目にしない。帯の丸には曜日、大きな丸には kcal と P・F・C の名前を添える
- 色は P・F・C と破壊的な操作と、アクセントだけに使う。状態（間に合うペースか）は色で分けず、文で示す

### 文字

システムのフォント（San Francisco、日本語はヒラギノ）を、iOS のテキストスタイルで使い、Dynamic Type に従う。数字は桁をそろえる（`monospacedDigit()`）。

| テキストスタイル | 使うところ |
|---|---|
| Large Title | 使わない（タイムラインの題はいま見ている日付、ほかは標準の題） |
| Title 2 | 体重の値、大きな丸の中の kcal |
| Headline | ナビゲーションバーの題、カードの見出し |
| Body | 一覧の行、会話、値の欄 |
| Subheadline | タイムラインのカードの本文、食事の名前 |
| Footnote | 一覧の見出しと注記、kcal と P・F・C の小さな数字 |
| Caption 1・2 | 時刻、帯の曜日、グラフの目盛り |

### 形と部品

- **一覧**: アカウント、食事の料理、目標の過去の目標は、iOS の設定と同じ角の丸い一覧（Inset Grouped）
- **タイムラインのカード**: 食事、体重の知らせ、目標の知らせ、週の振り返りは、角の丸い（12pt）白いカードにする。影は付けない
- **ボタン**: 主な操作（記録、始める、この目標で始める）は塗ったボタン（`.borderedProminent`）、並べる副の操作（あとで）は灰色のボタン（`.bordered`）
- **自分と相手**: 自分が書いた文はアクセントの色の吹き出しで右に寄せる。自分が記録した食事と体重も右に寄せ、アクセントの色を薄く敷いたカードにする。返ってきた発言は吹き出しにせず、左の地の上に文で置く（長い文を読みやすくする）。アプリからの知らせは全幅の白いカードにする
- **推定**: 推定したままの料理の量には、枠線だけの小さな「推定」の印を添える。直すと外す
- **アイコン**: SF Symbols の `camera.fill`（撮る）、`scalemass.fill`（体重。実装のときに、体重計に見える記号をほかの候補とも見比べる）、`person.crop.circle`（アカウント）、`chevron.right`（潜れる行）。文字で足りるところにはアイコンを付けない

### 余白と押せる範囲

HIG は余白の値を表で決めず、余白をそろえること、セーフエリアを守ること、システムのレイアウトガイドを使うことを求めている（Layout）。押せる部品は既定 44×44 pt・最小 28×28 pt で、部品の間の余白も大きさと同じくらい大事だとしている（Accessibility）。

- **余白は SwiftUI の標準に任せる**: `.padding()` の既定値、`List` の余白、`VStack`・`HStack` の既定の間隔を使い、自前の数値を持たない。Dynamic Type で文字を大きくしても、余白が合わせて変わる。コンポーネントの見本は、画面の端とカードの内側を 16 pt、カードの間を 12 pt、まとまりの間を 24 pt で描いている
- **押せる範囲は 44 pt 以上**: 見た目が小さい部品（プリセットのチップ、文字のボタン）も、押せる範囲は `contentShape` で 44 pt 以上に広げる。ステッパーの − と ＋ は見た目も 44 pt にする
- **枠のある部品の間は 12 pt 以上**: ステッパーの − と ＋ と値、入力欄のカメラ・体重・書く欄、並べたボタン（あとで・始める）の間。枠のない部品（文字のボタン）のまわりは 24 pt ほど空ける

### 1日の丸

- 1本の輪を、P・F・C の kcal で起点（上）から時計回りに色分けし、一周で1日の目安にする。色の間に細いすき間を空ける
- 目安を超えた日は、輪の起点に文字の色の点を付ける。目標がないあいだは、P・F・C の割合で一周させる
- 体重を記録した日は、帯の丸の中に灰色の点を付ける。日のまとめの大きな丸は中に kcal を書くので点を付けず、体重は「体重」の行で示す
- 大きさ: 帯の丸は 28pt・線 4.5pt、日のまとめの大きな丸は 128pt・線 14pt（中に4桁の kcal が収まる大きさ）
- 実装は Swift Charts の `SectorMark`（`innerRadius` と `angularInset`）で描ける

### グラフ

- Swift Charts で描く。縦軸は1本だけにする（体重と kcal を1つのグラフに重ねない）
- 系列は1色（アクセント）で、目安・目標の道筋は点線、グリッドは薄くする
- 1本のグラフに系列が2本あるとき（消費量と1日の目安）は、線の端に名前を直接添える

### 文言

- 「AI」「質問」「相談」という言葉を出さない
- 間に合わない週も責めず、事実だけを書く（「このままだと期限に 0.8 kg 届きません」）
- 知らせには、ふだんの様子と、次にできることだけを書く（「いつもはこの時間までに記録しています。食べたら撮っておきましょう。」）
- ボタンは、押すと起きることを動詞で書く（記録、始める、撮る）
- 戻せない操作のボタンは iOS に合わせて「削除」と書き、削除するものの名前を入れる（「食事を削除」「アカウントを削除」）
- 量は数と単位の間を空ける（「32 g」「72.4 kg」「510 kcal」）
- 日付は「9月24日（木）」「9月24日」と書き、期間は「9月18日〜24日」「8月28日〜9月3日」と書く。「9/24」の形は使わない

## 標準の部品で作るもの

HIG か SwiftUI に標準があるものは、それに従う。独自の振る舞いを作らない。

| 振る舞い | 標準 |
|---|---|
| 値が変わるときの動き | 数字は `contentTransition(.numericText())` でめくるように変え、1日の丸とグラフは `withAnimation` の既定の動きで伸び縮みさせる。「視差効果を減らす」設定では動かさない |
| 手応え（触覚） | `sensoryFeedback`。記録・撮る・目標が決まったときは `.success`、ステッパーの1段ごとは `.increase`／`.decrease` |
| グラフを押して値を出す | Swift Charts の `chartXSelection` で選んだ週・日の値をグラフの上に出す |
| 食事の写真を横に送る | `TabView` のページ表示（`.tabViewStyle(.page)`） |
| 行を左へ送って削除する | `swipeActions` と `role: .destructive`。VoiceOver のカスタムアクションは標準で付く |
| シート、確かめ | `sheet`（`presentationDetents`）、`confirmationDialog`、`alert` |
| 押して潜る | `NavigationStack` と `NavigationLink` |

## 色と文字の決め方

色と文字は、手で磨く往復をせず、根拠のある値で決める。根拠は2つ。

- **アクセシビリティ**: 文字は地に対して 4.5:1 以上、グラフの線と印は 3:1 以上、P・F・C の3色は色覚の型を問わず見分けられる。ライトとダークの両方で確かめる
- **意味**: ほかの食事管理アプリでの P・F・C の塗り分け、食べものからの連想、④のコンセプトの印象（淡々と記録できる、責めない、手応えがある）

コンポーネントは先頭行に `@dsCard` を持つので、あとから Claude Design の design-system プロジェクトに取り込める。引き継ぎでは、ここの「ルック&フィール」を `DESIGN.md` に書き出す。
