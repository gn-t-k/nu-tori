入力欄の「撮る」と「体重」の見分け

書く欄とプリセットが来るまでの、ボタンが2つだけのときにどう置くか。体重が未記録で2つとも塗られているときに見分けられるか。

決まっていること: 左から「撮る」「体重」、あとで書く欄（06-layout.md「タイムラインの並べ方と、1日の丸」の「入力欄」）。「撮る」はいつも Primary で塗り、「体重」は今日が未記録のあいだだけ Primary で塗る（DESIGN.md「入力欄」と composer-camera）。アイコンは camera.fill と scalemass.fill、押せる範囲は 44、枠のある部品の間は 12。

左に寄せる今の入力欄（「体重」だけが左端）の左に「撮る」を足す。右は書く欄が来るまで空いたまま。書く欄が来ても2つの位置は動かない。
真ん中に寄せる2つだけのあいだは、入力欄の真ん中に並べる。親指の届く真ん中にシャッターの入口が来る。書く欄が来たら左へ寄る（「文章と会話」で位置が変わる）。
文字を添える書く欄が来るまでの空きを使い、2つを文字つきのカプセルにして幅いっぱいに並べる。書く欄が来たら、アイコンだけの丸に縮める（07-components/README.md「名詞から始める」の、アイコンだけで示す形に戻る）。
未記録のときだけ文字ふだんは「左に寄せる」と同じ丸。今日の体重が未記録で塗るときだけ、「体重」を「今日の体重」のカプセルに広げる。記録すると丸に戻る。

撮っておいた写真を選ぶ

選んだ写真の食事を、タイムラインのどこに出すか。送った時刻の位置（決まった形）と、撮った時刻の日と位置に並べる案を比べる。複数枚を選んで、撮影時刻の近いものを1つの食事にまとめたときの見え方も描く。

決まっていること: 食事の時刻は撮影時刻（無ければ選んだ時刻）で、タイムゾーンは「写真からの推定の仕組み」の追記の「撮っておいた写真の時刻」。1日の集計は撮った時刻の日に入れる。入口はカメラの左下（2 で標準のカメラを選んだら、その案の入口）。例: 今は 9月24日（木）21:05。前の日の夕食の写真（9月23日（水）19:40 と 19:48）と昼食の写真（9月23日（水）12:10）を選んだ。まとめる幅は仕様で決める（ここでは仮に 30 分）。

送った時刻の位置（決まった形）06-layout.md のとおり、写真は送った時刻（今日の一番下）に出し、食事には撮った時刻を示す。丸が伸びるのは撮った日（水）。
撮った時刻の位置 ＋ そこへ送る食事を撮った時刻の日と位置に並べ、選び終えたらタイムラインをその位置へ送る。入った食事を一度だけ縁取りで示す。「土台と体重」で作ったタイムラインの枠（日で区切る、同じ日の中は実際の時刻の順）とそろう。
撮った時刻の位置 ＋ 1行で知らせる食事は撮った時刻の日と位置に並べるが、タイムラインは今の位置のまま。入った場所が画面の外なら、入力欄の上に1行で知らせ、押すとそこへ送る（答えていない知らせの1行と同じ形）。

カメラの許可

カメラを許可しなかった人が「撮る」を押したときに、どう見せるか。

推定の状態ごとの見え方

タイムラインのカードと、食事の画面の料理の一覧で、状態ごとにどう見せるか。料理なしを推定できなかったと分けるか。翌日に推定することをどう伝えるか。「料理を足す」を置くか。

決まっていること: 状態は、まだ送れていない・推定中・推定できた・料理なし（写っていない、見分けられない）・翌日に推定（回数切れ）・推定できなかった（「端末とサーバーの同期とオフライン時の振る舞い」の追記の「同期」）。回る印と「推定しています…」は推定中のときだけ（DESIGN.md「待っている表示」）。まだ送れていないあいだは待っている表示を出さず、写真と時刻だけのカードにする（同じ追記の「記録の持ち方」の「待っている表示」）。例: 今日の6つの食事を、それぞれの状態で並べた。

「料理を足す」を
料理なしをまとめる料理なしと推定できなかったを、同じ「料理を推定できませんでした」で見せる。翌日に推定は、回る印を出さずに「明日推定します」だけを書く。
分けて理由を書く料理なしと推定できなかったを分け、どちらも何が起きたかを書く。翌日に推定は、今日はもう推定できないことと、明日推定することを書く。カードには1行、食事の画面には2行で書く。
写真に印を重ねる状態を写真の縮小の上に短い印で重ね、カードの本文には名前の場所に短い文だけを置く。料理なしと推定できなかったは分ける。食事の画面は「分けて理由を書く」と同じ。

1日の丸と日のまとめの食べた量

kcal はあるが P・F・C がすべて 0 の日と、食事はあるが kcal がまだ無い日の丸。日のまとめに大きな丸と kcal・P・F・C を足した形と、丸の下に割合で一周することを添えるか。

決まっていること: 描き方は DESIGN.md「1日の丸」。この仕様では目標が無いので、P・F・C の割合で一周する。体重を記録した日は、帯の丸の中に灰色の点。推定中の食事は、推定が済むと丸が伸びる。日のまとめは、今の一覧（この日の体重、タイムラインでこの日を見る）の上に、大きな丸と kcal・P・F・C を足す（07-components/day-summary「目標がないとき」から、体重の傾向、目標を立てる、目標に触れる注記を抜いた形）。合計に「不明」が混じるときの添え方は 7 とそろえる。

どの案も同じ（案を分けない）ふだんの週。月〜水は食事と体重を記録済み、今日（木）は朝食が推定中。
下の案の例の週: 月＝ふだん、火＝kcal はあるが P・F・C がすべて 0（蒸留酒だけ）、水＝翌日に推定の食事だけ、今日＝推定中の食事だけ
空の輪のままkcal がまだ無い日は、食事の無い日と同じ空の輪にする。P・F・C がすべて 0 の日も、割合が無いので空の輪にする。日のまとめでは、丸の下に割合で一周することを添える。
点線の輪kcal がまだ無い日は、点線の輪にして「食事はあるが、まだ量が無い」ことを示す。P・F・C がすべて 0 の日は、灰色の輪で一周する。日のまとめに割合の説明は添えない。
灰色の輪「食べたが P・F・C で分けられない」ときは、どれも灰色の輪で一周する（kcal がまだ無い日も、P・F・C がすべて 0 の日も）。日のまとめでは、丸の下に割合で一周することと、灰色の意味を添える。
