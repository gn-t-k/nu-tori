# トレードオフは設計思想の順位で決める

設計の判断がぶつかったときは、次の順位で上にあるものを取る。

1. **ユーザーの操作を増やさない**: 精度を上げる操作は、いつでもできるが、しなくてよい
2. **先回りして気を利かせる**: システムが知りうること（ヘルスケアの値、いつもの時刻、前日の値、以前の修正）は、ユーザーに尋ねる前に使う。尋ねるときは初期値を入れておく
3. **値の確かさに応じて受け付け方を変える**: 厳密に測れる値（体重）は測った値だけを受け付け、測りにくい値（食事の量・栄養）は当てずっぽうでも受け付けてあとから直せるようにする
4. **仕組みを言い訳にしない**: 画面に「AI」という言葉を出さず、「間違うかもしれない」という言い訳もしない。推定であることは、読み込み中の表現や値の候補の出し方で伝える
5. **求められていないことは言わない**: アドバイスは尋ねられたときだけ出す。知らせは、記録忘れ、目標がないとき、目標の達成・期限、1日の目安の変更だけ
6. **モードレス**: どの操作も途中でやめられ、あとからやり直せる。起動直後に長い設定を求めない
7. **専用の画面より、小さな機能の組み合わせ**: 特定の作業に特化した専用画面を作らず、汎用的な小さな機能を組み合わせて使えるようにする
8. **拡張性**: 課金、他アプリとの連携、写真以外の記録方法を、今の構造を壊さずに足せるようにしておく

食事管理アプリの多くは、精度を上げるために入力を求める。nu-tori は続けられることを精度より上に置き、操作を1つ増やすくらいなら推定の精度が少し下がるほうを取る。ユーザーに求める操作は、朝に体重を入れることと、食べるときに撮ることの2つだけにする。
