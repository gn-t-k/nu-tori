# 記録の正本はサーバーが持ち、写真の本体だけは端末が持つ

記録（体重記録、食事、料理、材料、目標、1日の目安、会話と発言）の正本はサーバーが持ち、端末はキャッシュにする。AI の発言に渡す文脈をサーバーで組み立てられ、課金を後から足せ（ADR-0001 の拡張性）、管理者と推定精度の観測も足せ、機種変更はサインインし直すだけで済む。

写真だけは例外で、本体は端末が撮ったままの解像度でアプリの中に持ち、見返しは端末から読む。サーバーは推定に送る縮小版（長辺 1024px、EXIF を消したもの）を控えとして保管し、推定と推定し直し、端末に写真が無いとき（機種変更のあと）の復元に使う。原寸をサーバーに置いて表示のたびに読むと、オブジェクトストレージの容量と表示の速さが重くなるため。

## 検討した案

- 端末を正本にして CloudKit で同期する: サーバーの DB が要らず安いが、管理者や観測を足すときに結局サーバーにデータを持つことになり、同期の失敗も追いにくい
- 端末だけに持つ: 機種変更で、iPhone のバックアップから戻さない限り記録を失う
- 写真もサーバーを本体にする: 原寸を保管し、表示のたびにサーバーから読むことになり、容量と速さが重くなる

## 起きること

- iPhone のバックアップから戻さずに機種変更したときは、写真は縮小版に戻る
- 食事やアカウントを消すときは、アプリの中の写真とサーバーの控えを消す。写真ライブラリの写真（撮っておいた写真を選んだときの元）には触れない
- 撮っておいた写真の撮影時刻は、EXIF を消す前に端末が読み、食事の日時として送る
