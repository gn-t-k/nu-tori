# 初回リリースはタブを持たず、タイムラインを根にする

初回リリースの要件では、画面の根をタイムラインだけにし、タブバーは持たない。いちばん使うのは記録（撮る、体重、書いて送る）で、目標や傾向を見に行く頻度は低いので、タブは場所を取りすぎる。まとめて見せる情報は、タイムラインの上に固定した1日の丸の帯に詰め、丸から日のまとめを開く。目標は日のまとめ、体重の画面、タイムラインの目安の変更、知らせから開く。

これは初回リリースの要件から導いた判断で、タイムラインにすべてを詰め込む決まりではない。記録と同じくらいの頻度で開く場所が要件に加わり、帯や日のまとめに無理なく収まらなくなったら、タブで整理することを検討し直す。

## 検討した案

- 2タブ（今日／目標）: 目標を開く頻度に対して、タブが場所を取りすぎる
- 2タブ（今日／タイムライン）、2タブ（タイムライン／進み具合）: 食事と栄養の情報と、体重と目標の情報が別々の場所に散らばる
- タイムラインだけ（帯なし）: 目標期間の傾向、目安の推移、目標の切り替えの入口が弱い
- タブなしで、一番上に目標の要約・カメラのファインダー・習慣トラッカー・1日の目安を置く: 一番上が詰まり、新しいものを下に並べると上に集めたものとぶつかる

根拠: `docs/ui-design/0001-first-release/05-navigation.md` の「根（目標地点）」。各案のプロトタイプは `prototype/0001-navigation`、`prototype/0001-timeline`、`prototype/0001-tabs`、`prototype/0001-chat-rings` の各ブランチにある
