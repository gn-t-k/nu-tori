# リポジトリを公開し、競合を禁じるライセンスを付け、外からの書き込みは受けない

nu-tori は健康の記録を扱い、あとから課金も足す（ADR-0001 の拡張性）。それでもリポジトリは公開して開発する。公開しても問題のない質で作ることを前提にしている。公開すると GitHub Actions の標準の macOS ランナーが無料になり、どのエージェントが出した PR でも、iOS のビルドと UI テストを費用を気にせず回せる。代わりに、コード、AI へのプロンプト、Issue での設計の議論を誰でも読めるようになることを受け入れる。

公開するのは CI のためで、外からの貢献を集めるためではない。ライセンスは PolyForm Shield 1.0.0 にする。読むことと、競合しない使い方は認める。nu-tori と競合するものを出すことは、無料でも期限なく禁じる。Issue と PR を作れるのは書き込み権限を持つ人だけにし、すべての会話をロックして、外の人はコメントも書けないようにする。利用者の要望は、アプリの問い合わせで受ける。

## 検討した案

- 非公開のまま、手元の Mac を self-hosted runner にする: Mac を閉じている間は CI が止まり、クラウドのエージェントの PR を確かめられない
- 非公開のまま、macOS ランナーの料金を払う: エージェントが直して push するたびに費用がかさみ、CI を回すのをためらうようになる
- ライセンスを付けない: 競合は防げるが、手元で動かすことも許さないことになる。付けていないのが意図か付け忘れか、外からは分からない
- MIT などのオープンソースのライセンス: 同じアプリを出されても止められない
- FSL（Functional Source License）: 禁じるのは商用で競合するものだけで、版ごとに2年たつと MIT か Apache-2.0 に変わり、同じアプリを出せるようになる
- 誰でも Issue と PR を出せるようにし、外のコードは書き直して取り込む: 荒らしへの対応と、外の書き込みがエージェントを操る危険を抱える。利用者の要望は問い合わせで足りる

## 起きること

- 他人は Issue・PR・コメントを書けない。エージェントが読む外の文は、bot の PR の本文（依存先のリリースノートなど）に限られる
- 新しい Issue と PR は、作られたときに Actions のワークフロー（`.github/workflows/lock-conversations.yml`）でロックする
- 鍵と利用者のデータはコミットしない。開発者自身の健康データも、開発者が良いと言ったものを除いてコミットしない。鍵は push protection でも止める
- Actions の秘密の値は、main からだけ使える Environment に置く。ブランチに push したワークフローからは読めない
- nu-tori をやめたら、他人が引き継いで出してよい（ライセンスの「Discontinued Products」）
- `.agents/skills/` は mattpocock/skills の写しで、MIT のまま使う。表示は `LICENSE.md` の末尾に置く
- 非公開に戻しても、それまでに公開した内容は写されているかもしれない。出した版に付けたライセンスは取り消せない
