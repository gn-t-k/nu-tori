# kcal は栄養の出どころの値を使い、P・F・C から出し直さない

料理と食事の kcal は、材料ごとの栄養の出どころ（栄養成分表示、成分表、AI の推定）の kcal に量を掛けて足したものにし、P×4 + F×9 + C×4 で出し直さない。端末の表示（1日の丸、日のまとめ、週の振り返り）、サーバーの計算（推定消費量、1日の目安）、ヘルスケアに書くエネルギーのすべてで、この数え方を使う。成分表の kcal は FAO/INFOODS 方式で、アルコールや食物繊維の分も含む。P・F・C から出し直すと、アルコールの kcal が消え、成分表や栄養成分表示の値ともずれる。

1日の丸の P・F・C の長さは、その日の P×4 : F×9 : C×4 の比で総 kcal を按分する。どの長さも g × 4/9/4 と一致するとは限らない。

## 検討した案

- kcal = P×4 + F×9 + C×4: 1日の丸の P・F・C の長さの合計が総 kcal とぴったり合う。アルコールの分が消え、成分表の kcal とも数%ずれる
- kcal は成分表の値を使い、1日の丸では P×4・F×9 を引いた残りを C の長さにする: 表示の kcal と長さの合計は合うが、高たんぱくの食品や栄養成分表示の丸めで P×4 + F×9 が kcal を超える日に、C の長さがマイナスになりうる

## 起きること

- ユーザーが P・F・C の g から暗算した kcal と、アプリの kcal は少し違う
- 使い始める前の食べた量には、他のアプリがヘルスケアに書いた kcal をそのまま使う

今の決定は、`server/AGENTS.md` の「端末とサーバーの両方に置く決めごと」と、`DESIGN.md` の「1日の丸」にある。

根拠: 「推定消費量と1日の目安の計算法」（Issue #31）の解決コメント
