# 本番で起きたときの手順

本番で障害・鍵の漏れ・個人情報の漏えいが起きたとき、費用の知らせが来たときと、アカウントを手で止めるときの手順。ここには、このアプリに固有の事実と、起きる前に決めておいた判断だけを書く。コマンドの細かい使い方や報告の様式のような一般の手順は、公式の文書を指す。決めた経緯は「[障害・鍵の漏れ・個人情報の漏えい・アカウントの停止の手順を決める](https://github.com/gn-t-k/nu-tori/issues/640)」の解決コメント。

告知と、アカウントを止めた印は、仕様「告知と利用の停止」（「[一般公開の準備の決定の索引と、仕様への申し送り](https://github.com/gn-t-k/nu-tori/issues/599)」の仕様の行）で作り、まだ無い。入るまでの手順は、それぞれの節に書く。

リポジトリは公開している（ADR-0010）。起きたことを Issue・PR・コメントに書くときも、アカウント ID、漏れた中身、ユーザーの記録は書かない（`docs/agents/tooling.md` の Sentry・Cloudflare・PostHog を読む節の決まりと同じ）。

## 気づく

- 例外: 本番の知らせ（`docs/agents/tooling.md` の「本番の知らせを Issue にする」）
- Worker が丸ごと落ちたとき: Sentry の Uptime のモニター（Developer の枠に1つある）が、本番の `https://api.nu-tori.app/health` を呼び、落ちたら Sentry のメールで知らせる。`/health` は D1 を読めなければ 503 を返す（`server/AGENTS.md` の「デプロイ」）
- 推定の提供元: Anthropic の status のページ（status.anthropic.com）
- 鍵の漏れ: リポジトリの secret scanning と push protection を有効にしている（2026-10-20 に確かめた）。GitHub のメールで知らせが届く
- 委託先の漏えい: Cloudflare・Anthropic・Sentry・PostHog から、それぞれのアカウントのメールに届く
- 費用: Anthropic のワークスペースの知らせと、PostHog の無料枠のメール（下の「費用の知らせ」）

## 障害

1. 直した版を出す（`server/AGENTS.md` の「デプロイ」）。依存の更新で壊れたときは `docs/agents/dependencies.md` の「壊れたときの戻し方」、古いアプリのビルドで困るときは `docs/agents/ios-release.md` の「古いビルドの締め出し」
2. 直した版を出しても記録が元に戻らないときだけ、記録を戻す（下の「記録を戻す」）
3. 1時間を超えて使えなくなりそうなら、ユーザーに知らせる（下の「ユーザーに知らせる」）

### 記録を戻す

| 置き場 | 中身 | 戻し方 |
|---|---|---|
| Durable Object | 記録の全部（アカウントごとに1つ） | PITR で過去 30 日の任意の時点に戻せる。Durable Object の中で `ctx.storage.getBookmarkForTime(時刻)` を取り、`onNextSessionRestoreBookmark(ブックマーク)` のあと `ctx.abort()` で戻す。呼ぶ経路は今は無く、要るときに足す。戻す前の時点のブックマークが返るので、戻したことも取り消せる |
| D1 | アカウント、セッション、暗号化した Apple の認可 | `wrangler d1 time-travel restore` で過去 30 日に戻せる。戻した時点よりあとに作ったアカウントは D1 から消え、Durable Object の記録だけが残る |
| R2 | 写真の縮小版 | 戻せない。バックアップも取らない（写真は推定のあとは見せるだけで、写しを増やさない） |

調べた事実は `docs/research/server-deploy.md` の「消去と復元」。

### 推定の提供元が止まったとき

別の提供元に切り替える仕組みは持たない。推定と返事は約 16 分やり直してから断念し、アプリに「推定できませんでした」「返事を作れませんでした」を出す（`server/AGENTS.md` の「推定」と「返事」）。

1. Anthropic の status のページで止まっていることを確かめる
2. 1時間を超えそうなら、ユーザーに知らせる
3. 戻ったら、断念した推定を送り直してもらうよう知らせる

上限に届くかクレジットが尽きたときは、すべての推定が断念になり、すべての文章が会話になる（`server/AGENTS.md` の「構成」）。下の「費用の知らせ」に進む。

### ユーザーに知らせる

全員への告知と、`nu-tori.app` の告知のページの両方に出す。アプリが開けない障害でも、ページなら読める。

告知の仕組みが入るまでは、`nu-tori.app` だけに出す。告知のページ（`https://nu-tori.app/announcements`）には、告知のファイルを1つ足して main に入れれば出る（足し方は `site/AGENTS.md` の「告知を足す」。`deploy-site.yml` が出す）。

## 費用の知らせ

本番の費用の上限は、ふだんの使い方では届かない止め金で、人が増えたことは知らせで追う。決めた経緯は「[公開の規模に合わせて、提供元と観測の道具の費用の上限を決める](https://github.com/gn-t-k/nu-tori/issues/636)」の解決コメント。

| 道具 | 上限と知らせ | 届いたとき |
|---|---|---|
| Anthropic（ワークスペース `nu-tori-production`） | 月の上限 $300。知らせは $50・$100・$200（1人の月の中央値で、約20・40・75人分）。前払いのクレジットは「$30 を下回ったら $100 まで」自動で補充する。組織は Scale の段階で、段階の上限（月 $200,000）には届かない | 上限は 400、残高ゼロも止まる。翌月か、上げるか補充するまで全員の推定が断念になる |
| Sentry | 無料のプラン（エラー月 5,000 件）。spike protection をオンにしている | 超えた分は捨てられ、請求されない。その月の残りのエラーが見えない |
| PostHog | 無料のプラン（出来事が月 100 万件）。カードは登録していない | 超えた分は永久に捨てられる。無料枠の 80% と 100% でオーナーにメールが届く |

### Anthropic の知らせが来たとき

1. 本番の PostHog で、使っている人の数と1人あたりの推定と返事の回数を見る（`docs/agents/tooling.md` の PostHog を読む節）
2. 人数のわりに回数が多い、または一部のアカウントに偏っていれば、不具合か使われ方を疑う。不具合なら「障害」、利用規約に反する使い方なら「アカウントを手で止める」に進む
3. 見込みどおりに人が増えていて、次の知らせか上限に月内に届きそうなら、上限を上げる。止め金の額は開発者が1か月で失ってよい額なので、上げる額は開発者が決める。知らせも、約何人分かで読める額に並べ直す

上限に届いて止まったときも同じ順で見て、上げたら「推定の提供元が止まったとき」の 3 のとおり、断念した推定を送り直してもらうよう知らせる。

自動の補充が失敗したとき（カードの期限切れなど）は、Anthropic の Console の請求のページで支払い方法を直し、クレジットを買う。

### Sentry と PostHog の枠

- Sentry: 毎月エラーの枠に届くようになったら、Team のプラン（月 $29、エラー月 5 万件）に上げるかを決める
- PostHog: 無料枠の 80% のメールが来たら、カードを登録して請求の上限（billing limit）を付けるかを決める。PostHog の数字は、推定と返事の原価と1日の回数の上限の見直しに使うので、捨てられると困る

## 鍵が漏れたとき

1. 下の表で、その鍵の入れ替え方を見る。順は、新しい値を置く → 動くことを確かめる → 古い値を無効にする
2. 漏れていたあいだに、その鍵で個人データを読めたおそれがあれば、「個人情報が漏えいしたとき」に進む（表の「漏れたときの危険」に「読める」とあるもの）

| 鍵 | 置き場 | 発行するところ | 漏れたときの危険 | 入れ替えるときの注意 |
|---|---|---|---|---|
| `CLOUDFLARE_API_TOKEN` | GitHub の Environment `development` と `production` | Cloudflare の API Tokens | 大きい。Worker を書き換えられ、本番の記録を読める | 同じ権限（`server/AGENTS.md` の「デプロイ」）で作り直す。入れ替えたら Cloudflare の監査ログで、漏れていたあいだの操作を見る |
| `APPLE_PRIVATE_KEY`・`APPLE_KEY_ID` | Worker（両方の環境） | Apple Developer の Keys（Sign in with Apple） | このアプリの名前で Apple の認可を交換・取り消す要求を作れる | 新しい鍵を作る → 両方の環境で2つを同時に替える → 開発用でサインインとアカウントの削除を確かめる → 古い鍵を失効させる。古い鍵を先に失効させると、サインインとアカウントの削除が 500 になる。保存済みの Apple の認可が新しい鍵で取り消せるかは確かめていないので、入れ替えたあとに本番のアカウントの削除が Sentry に失敗を出さないか見る |
| `APPLE_REFRESH_TOKEN_KEYS` | Worker（両方の環境） | 自分で作る 32 バイトの乱数 | D1 と一緒に漏れると、Apple の認可を読める | `版:鍵` の並びの末尾に新しい版を足す。保存とサインインのたびに新しい版で書き直されるが、古い行を暗号化し直す仕組みは無い。古い版を消すと、その版の行のアカウントの削除が止まるので、消すときは暗号化し直すスクリプトを書いてから |
| `APPLE_SUB_HASH_KEYS` | Worker（両方の環境） | 自分で作る 32 バイトの乱数 | D1 と一緒に漏れると、Apple の sub を試して、無料体験を使った Apple ID か（退会した人か）を確かめられる | `版:鍵` の並びの末尾に新しい版を足す。退会のときに新しい版で書き、サインインのときは残っている版の全部で引く。古い行は元の sub が無く書き直せないので、古い版は消さない。消すと、その版で残した人が退会して作り直したアカウントで、また無料体験を受けられる |
| `ANTHROPIC_API_KEY` | Worker（環境ごとのワークスペースのキー） | Anthropic の Console | 費用を使われる | 新しいキーを置いてから古いキーを無効にする |
| `POSTHOG_PERSONAL_API_KEY` | Worker（本番だけ） | PostHog の個人の API キー（`person:write`） | 利用の数の人を消せる・読める | 新しいキーを置いてから古いキーを消す。無効なキーのあいだは、アカウントの削除が 500 になる |
| `BETTER_AUTH_SECRET` | Worker（両方の環境） | 自分で作る乱数 | 小さい。今の設定では、セッションも保存したデータも、この値では守っていない | 替えるだけ。セッションは切れない |
| `E2E_SIGN_IN_SECRET` | 開発用の Worker と、GitHub の Environment `development` | 自分で作る 32 文字以上の乱数 | 開発用の環境に誰でもアカウントを作れる（本番には置かない） | 2か所を同じ値に替える。食い違うと `verify-development` が 401 で落ちる |
| `DEPENDENCY_APP_PRIVATE_KEY` | GitHub の Environment `dependency-updates` | このリポジトリ用の GitHub App の設定 | リポジトリに書ける | 新しい秘密鍵を作って置いてから、古い秘密鍵を消す |
| `NU_TORI_SENTRY_READ_TOKEN` | GitHub の Environment `production-alerts` と、エージェントの環境 | Sentry の個人のトークン | 本番の例外を読める | 作り直して両方に置く |
| `SENTRY_AUTH_TOKEN` | Xcode Cloud のワークフローの Environment | Sentry の組織のトークン | dSYM を上げられる | 作り直して置く |
| エージェントが読む値（`NU_TORI_ASC_*`、`NU_TORI_CLOUDFLARE_READ_TOKEN`、`NU_TORI_POSTHOG_READ_KEY`） | `docs/agents/tooling.md` の、それぞれを読む節 | App Store Connect、Cloudflare、PostHog | TestFlight のフィードバック、本番のログ、利用の数を読める。App Store Connect の鍵はフィードバックを消せる | 作り直して、同じ節の置き場に置く |
| Sentry の DSN（`SENTRY_DSN` と iOS）、PostHog のプロジェクトの token（`POSTHOG_PROJECT_TOKEN` と iOS） | Worker と `ios/NuTori/Observability/ObservabilityKeys.swift` | Sentry と PostHog のプロジェクトの設定 | 小さい。アプリに入れて配る値で、偽の出来事を送られるだけ | 偽の出来事で困ったときだけ替える。iOS は新しいビルドが要り、古いビルドは古い値に送り続ける |

App Store Server API の鍵（課金で足す）のように新しい秘密の値を足したら、この表に行を足す。

## 個人情報が漏えいしたとき

個人情報保護法 26 条の報告と本人への通知。個人で運営していても例外は無い。事実は個人情報保護委員会のガイドライン（通則編）の 3-5 と、同 Q&A の 6 章。

### 報告するか

漏れた「おそれ」があれば報告する側に倒す。確証が無くても、窃取の痕跡や、委託先・公的機関からの根拠のある連絡があればおそれに当たる。次のどれかに当たれば報告する（施行規則 7 条）。

- 不正アクセスなど、不正の目的によるおそれがある（人数にかかわらない。委託先や使っているサービスへの不正アクセスも含む）
- 本人が 1,000 人を超える（数えられないときは、最大で超えうるなら）
- 要配慮個人情報を含む。本人が入れた体重・体脂肪率・食事・kcal は当たらない。会話の文章は病名や受診の事実を含みうるので、会話が漏れたおそれがあれば、含むものとして扱う
- 財産の被害が起きうる

保存の暗号化は Cloudflare が鍵ごと持つので、高度な暗号化で報告が要らなくなる場合（Q&A 6-19）には頼らない。

### 期限

| 何を | いつまでに | 法の定め |
|---|---|---|
| 速報 | 知った日から 3 日以内 | 速やかに（目安は概ね 3〜5 日） |
| 確報 | 知った日から 30 日以内。不正の目的によるおそれがあれば 60 日以内 | 規則 8 条 2 項 |

知った日を 1 日目に数え、土日と祝日も数える。委託先から連絡を受けたときは、受けた日が知った日になる。報告は個人情報保護委員会のホームページの報告のフォームから出す。速報は、そのとき分かっていることだけでよい。

### 本人に知らせる

漏れたおそれのある本人のアカウントに告知を出し（告知の仕組みが入るまでは公表だけになる）、あわせて `nu-tori.app` の告知のページに公表する。公表は、告知のファイルを1つ足す形で出す（`site/AGENTS.md` の「告知を足す」）。問い合わせ先（`support@nu-tori.app` とフォームのあるサポートのページ）は、告知のページが告知の下に足す。メールアドレスを持たないので公表だけで足りる道もあるが、アプリで届けられるのに公表だけにするのは、通知が困難とは言いにくい。

知らせる中身は、何が起きたか、漏れた項目、原因、起きうる二次被害、ユーザーが自分でとれること。公表には特定の個人が分かることを書かない。

## アカウントを手で止める

利用規約の「禁止すること」をしたアカウントを止めるとき。利用規約はまだ公開していない。中身は「[利用規約と特商法の表記の中身を決める](https://github.com/gn-t-k/nu-tori/issues/593)」の解決コメントにあり、「利用の停止」の項には、知らせたうえで止めることがある、とだけある。

### 今の手順

止めた印が無いので、できるのはセッションを消すことだけ。その人はすぐ締め出されるが、Apple でサインインし直せば戻れる。

1. そのアカウントの `session` の行を消す（`wrangler d1 execute nu-tori-production --remote --env production --command "<SQL>"`）
2. 同じ人がサインインし直して同じことを繰り返したら、仕様「告知と利用の停止」を先に進めるよう、開発者に伝える

### 仕様「告知と利用の停止」が入ったあとの手順

1. 止める前に、そのアカウントに告知を出す（理由と止める日）。被害が広がっていて急ぐときは、2 を先にして、止めたあとに知らせる
2. D1 の `user` の行の `banned` を立て、そのアカウントの `session` の行を消す。`banned` だけでは今のセッションが使えるままになり、セッションを消すだけではサインインし直せば戻れるので、両方する
3. その人がサインインし直すと断られ、アプリが利用を止めたことと問い合わせ先を出す
4. 解くときは `banned` を戻す

止めてもサブスクリプションは止まらない。解約は本人が行い、返金は Apple の手続きに任せる。

## テストユーザーを足す・外す

開発者と手伝いの人が払わずに使うアカウントは、D1 の `test_users` に行を足して、いつもサブスクリプション中と同じに扱う。管理画面は無いので、`wrangler d1 execute` で書く（開発用は `nu-tori-development` で `--env production` を付けない）。

1. アカウント ID（`user` の `id`）を、その人のサインインした時刻などから `user` の表で確かめる
2. 足す: `wrangler d1 execute nu-tori-production --remote --env production --command "INSERT INTO test_users (account_id) VALUES ('<アカウント ID>')"`
3. 外す: `wrangler d1 execute nu-tori-production --remote --env production --command "DELETE FROM test_users WHERE account_id = '<アカウント ID>'"`

旗の変化は、サブスクリプションの状態の変更を足す時機に端末へ届く: 無料体験とサブスクリプションの区切りの時刻のアラーム（無料体験中に立てたら、あと3日の日の始まりまでに届く）と、取引・取り消しを書いたとき。切れているアカウントに立てたときは、保留した推定があれば、次の送る要求で張るアラームで届き、保留した推定も再開する。保留した推定が無い切れたアカウントには、次に変更を足す時機（取引を書くなど）まで届かない。退会すると行は消える（CASCADE）。
