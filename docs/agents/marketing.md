# マーケティングの判断

App Store の掲載情報は、名前・サブタイトル・キーワード・説明文・プロモーション用テキスト・スクリーンショットの見出しを指す。

- 判断には根拠を添える。根拠は、出典つきの調査（`docs/research/`）か、計測の数字（App Store Connect のキャンペーンごとの数、Cloudflare Web Analytics、PostHog）
- 根拠が開発者の実感や一般論だけのときは「推測」と書き、確かめる段取り（外部テスターへの聞き取り、LP の A/B、プロダクトページの最適化）を添える
- 競合のレビューを引くときは、書いた人の名前を書かず、短い抜粋だけにする

**Why:** 「一般公開の準備の範囲と方針を決める」（#592）で、「『AI 食事管理』がよく検索される」という推測を事実のように出し、開発者に指摘された。検索の回数は一次の情報からは取れず、確かめると大手は名前に「AI」を入れていなかった。

## アプリを入れていない人の語で書く

- LP と App Store の掲載情報では、アプリを入れていない人が読んで分かる語で書く。`GLOSSARY.md` の語（1日の目安、推定消費カロリー、見直し、無料体験の最後の日など）は、アプリの画面の名前（「1日の目安が変わりました」の知らせなど）を見せるときだけ使う

**Why:** 「App Store の掲載情報を決める」（#597）で、プロモーション用テキストの案を「1日の目安は、毎週の体重の動きで自動で直ります」と出し、開発者に「初見の人には何のことか分からない」と直された。`GLOSSARY.md` の語は、アプリを使っている人に向けた語。

## 病気に効くとは書かない

- LP と App Store の掲載情報では、nu-tori が病気の診断・治療・予防に役立つとは書かず、そう受け取れる書き方もしない。肥満症・糖尿病・メタボリックシンドローム・高血圧・生活習慣病などの病名を、効き目と結びつけて出さない。書けるのは、健康な人が食事と体重を記録して管理することまで
- 「医療機器ではありません」と書き添えるのはよいが、書き添えても上の書き方は許されない

**Why:** プログラムが医療機器に当たるかは、機能だけでなく、表示や広告が示す使い道でも決まる。病気の予防などをうたうと、機能が同じでもプログラム医療機器になりうる（`docs/research/launch-legal-checks.md` の問い1）。
