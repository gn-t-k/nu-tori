# PR の見張り

## UI テストの結果

`docs/agents/review.md` の表で UI テストの全件がかかる PR は、CI が緑でも、その全件の回の結果（回し方は `ios/AGENTS.md` の「確かめる」）が PR の本文の `## 確かめ` にそろうまで、merge できる状態に入らない。そろったとは、`## 確かめ` に書いた全件の回のコミットが PR の先頭のコミットと同じで、通っていること。

Mac の結果を頼むときは、開発者が Mac のセッションに貼るプロンプトを次の形で渡す。結果は PR のコメントで届くので、届いたらコミットと結果を本文の `## 確かめ` に書き、添えられたスクリーンショットは本文の Evidence に貼る（`docs/agents/git.md`）。

```text
gn-t-k/nu-tori の #<PR> のコミット <SHA> で scripts/check ios-ui-test を回して、結果をその PR にコメントしてください。
全件で15分ほどかかるので、コマンドの時間の制限を延ばすか、裏で回す。
コメントには、コミットと、通ったか、落ちたらテストの名前と失敗の要約を書く。
<見た目が変わる PR なら次の1行を足す>
変えた画面（<画面と、それを写す UI テストのスクリーンショットの名前>）のスクリーンショットを xcresult から書き出し、gh の --attach でそのコメントに添える。
```

## merge の条件の節

PR の本文の `## merge の条件` の段が `1段目` の PR は、`docs/agents/review.md` の「1段目」の merge の条件のとおりにそろうまで、merge できる状態に入らない。merge するのは PR を出したセッションで、ここでは、そろっているかを見て、そろっていないものを PR を出したセッションに返す。

- 照合と確かめの節の照らしたコミットが先頭のコミットと違っても、そのあいだが main や前のブランチを取り込んだだけの merge コミットなら、そろっていると読む（`git log --no-merges <照らしたコミット>..<先頭のコミット> ^origin/<マージ先のブランチ>` が空で、そのあいだの merge コミットの `git show --remerge-diff` が空）
- `## 仕様の照合` は PR を出す前に1回だけ回すので、節があればそろっていると読み、照らしたコミットを先頭と比べない
- 段が `待つ` か `調べもの` の PR は、この節では見ない
