# 共通ルール（全フェーズ）

## プロジェクトの決まりが先

要件サマリーの「プロジェクトの決まり」（ADR、`AGENTS.md` などで決まった DB の使い方）は、このスキルのルールより先に当てる。ぶつかったら決まりに従い、どのルールをどの決まりで置き換えたかを設計判断に書く。

## 判断の書き方

- 判断には、選んだ案と選ばなかった案それぞれの pros/cons を、この要件での具体的な得失で書く。「原則に従う」「原則に反する」は理由にしない
- エンティティや属性を「今の要件では要らない」として外すときは、次の2つを書いてから、外すかをユーザーに委ねる
  1. **将来の要件**: それが要るようになる具体的な場面
  2. **後方互換**: そのとき足すなら、既存のデータとの互換を保てるか

## セルフレビュー

- [ ] プロジェクトの決まりを先に当て、置き換えたルールを設計判断に書いたか
- [ ] 設計判断が pros/cons で書かれているか
- [ ] 外したエンティティと属性に、将来の要件と後方互換の検討があるか
- [ ] ユーザーに確かめる判断に「⚠️ 要確認」を付けたか
